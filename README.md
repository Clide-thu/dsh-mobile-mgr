# DSH 远程主机（Android）

在手机上管理多台远端 DSH 主机：**导入 SSH 配置 → 在 App 内管理 SSH 密钥 → 保存 DSH 凭证 → 点一下「打开」→ App 在手机上建立 SSH 隧道 →（默认）在 App 内置 WebView 里自动打开远端 `dsh web` 的完整 Web UI**。

需要时也可以改用「复制含 token 的网址 → 浏览器地址栏粘贴打开」的方式（见下文 A/B 两种模式）。
**v0.2.5 起，打开方式（内置页面 / 外部浏览器）和内置页面的顶部横栏收起，都改为主页「更多 → 设置」里的全局设置。**

远端不需要安装任何东西，也不需要改配置——手机就是那台「会自己开隧道」的客户端。

> **v0.2.5 新行为：打开方式改为全局设置 + 内置页面顶部横栏可收起**
>
> * **默认（推荐）：App 内置 WebView 全自动打开。** 点「打开」后 App 自己在隧道内完成 token 交换、
>   把 `dsh-auth-*` 登录 cookie 注入内置 WebView，再加载**不含 token** 的 `http://127.0.0.1:<隧道端口>/`；
>   不需要外部浏览器，也不需要你粘贴任何东西。
> * **可选：通过外部浏览器连接**（主页「更多」→「设置」开启）。开启后点「打开」，App 把含 token 的完整网址
>   `http://127.0.0.1:<隧道端口>/?token=…`（**原封不动**）以敏感内容复制到剪贴板，并打开**默认浏览器首页**；
>   你在浏览器**地址栏粘贴**打开即可登录。开启开关时会弹一次安全告警，开关旁的 **?** 可查看完整说明。
> * **每主机的「打开时在网址中附加 token」开关已在 v0.2.5 删除**（`appendToken` 字段一并移除）。升级后旧主机的
>   选择不再生效，统一跟随全局开关（默认 = 内置 WebView）；旧版加密数据里多余的字段会被安全忽略，不需要迁移。
> * **内置页面顶部横栏可收起**：设置页的「自动收起内置页面的顶部横栏」（默认开启）控制。展开态 56dp
>   （返回 + 标题 + 副标题 + 收起按钮），收起后是一行 32dp 的主机名（点按该行展开）；页面向下滚动自动收起、
>   滚回顶部自动展开。横栏只占自己的高度，**不覆盖页面内容**。
> * 两种打开方式的区别与切换见 [§4.1](#41-v024-的两种打开方式)；设置与横栏操作见
>   [docs/install.md §4](docs/install.md#第-8-步看到远端-dsh-ui)。
>
> 此前版本要点：v0.2.0 App 内 SSH 密钥管理（旧内联私钥自动迁移）；v0.2.1 打开前 token 预校验；
> v0.2.2「附加 token」开关 + 长按「复制打开网址（含 token）」；v0.2.3 的 token 交接对话框已被 v0.2.4 取代；
> v0.2.4 引入 A/B 两种打开方式与内置 WebView。
>
> 这是一个**侧载（sideload）**的原生 Android APK：没有上架应用商店、没有自动更新。
> 本项目**尚未在真机/模拟器上做过完整验收**，第一次使用请照着 [docs/install.md](docs/install.md) 一步步来。

## 1. 它适合谁

* 你在电脑上（或服务器上）跑着 `dsh web`，想在**手机上**打开同一个 Web UI。
* 那台主机只能通过 **SSH 登录**（比如校园网里的机器、要经过跳板机的机器）。
* 你不想在手机上装 Termux、也不想手工敲 `ssh -L`。
* 你希望**每台手机用自己独立的一把 SSH 密钥**，不和电脑/其他 App 共用私钥——v0.2.0 的密钥管理就是为此设计的。

如果你已经用反向代理 / 内网穿透 / Tailscale 把远端 DSH 暴露成一个**手机能直接访问的网址**，也可以直接把 App 当作「书签 + 快捷打开」使用（访问方式选「直接网址」），不需要 SSH 隧道。

## 2. 与桌面插件 DSH Remote Hosts 的对照

桌面端有一个 DSH 插件 `dsh-remote-hosts`（在 DSH 应用内使用）。本 App 是它的移动端对应物，能力对比如下：

| 能力 | 桌面插件 `dsh-remote-hosts` | 本 Android App |
|---|---|---|
| 主机列表来源 | 自动读电脑上的 `~/.ssh/config` | **导入** SSH config 文本/文件（手机无权读别的应用的 `~/.ssh`） |
| SSH 密钥 | 复用系统 `~/.ssh` 里的密钥（含 ssh-agent） | **App 自带密钥库**：可生成/导入/查看密钥对，主机只引用 keyId |
| 保存的凭证 | 每台主机 `端口 + token` | 加密保存 `端口 + token`；SSH 材料在密钥库（同一加密文件） |
| SSH 隧道 | 拉起 `ssh -L` 子进程 | App 内 JSch 会话做本地端口转发 |
| 打开 DSH UI | DSH 右侧栏内置浏览器标签 | **默认：App 内置系统 WebView（全自动，不跳外部浏览器）**；设置页开启「通过外部浏览器连接」时：复制完整网址 → 系统默认浏览器地址栏粘贴打开 |
| 多主机 | 左侧栏主机列表 + 状态 | 主机列表 + 状态 chip + 前台服务常驻通知 |
| 跳板机（ProxyJump） | 依赖系统 ssh 的 `ProxyJump` 配置 | 支持单级 `user@host:port` 或列表中的别名；跳板与目标各确认一次指纹 |
| 主机密钥校验 | 由系统 ssh / known_hosts 负责 | 首次连接确认指纹（TOFU），之后密钥变化会拦截 |
| 后台常驻 | 随 DSH 桌面应用运行 | Android 前台服务（通知栏可见） |
| 断线处理 | 打开时按需确保/复用隧道，失败返回错误分类 | **不自动重连**：隧道断了再点一次「打开」 |
| 更新方式 | 插件安装器 | 手动下载新 APK 覆盖安装（0.1.0 → … → 0.2.5 可保留数据） |

> 桌面插件还会显示只读的 workspace/session 面板；本 App **只负责打开远端 DSH 的完整 Web UI**，不额外做面板。

## 3. 5 分钟快速开始

### 0. 先确认三样东西（电脑 / 远端上操作）

| 需要什么 | 从哪里拿 |
|---|---|
| 远端主机的 SSH 登录信息 | 你平时 `ssh` 用的那个地址，例如 `user@192.0.2.10`、端口 `22`（或自定义端口） |
| 远端 `dsh web` 的**凭证 URL** | 在远端机器上启动/查看 `dsh web` 时打印的 `http://127.0.0.1:<端口>/?token=<令牌>`（见 [§4](#4-如何获取-dsh-凭证-url)） |
| 电脑上的 `~/.ssh/config` 文本（可选） | 用记事本打开，全选复制；没有 config 就跳过，手动「添加主机」 |

### 1. 把 APK 传到手机（电脑 / 手机上操作）

APK 在项目的 `dist/` 目录里，v0.2.5 的文件名是 `dsh-remote-hosts-0.2.5.apk`：

> **当前交付版本**：v0.2.5（versionCode 7）｜**751845 字节（约 0.72 MB）**｜SHA256：
> `b6c613b682a093d0aea02edf987fd5a2d2de23a1f1a16cbd53f55d511434a1d9`
> （核对方法见 [docs/install.md §1](docs/install.md#1-安装前的要求)）。
> 如果你拿到的是自己重新构建的 APK，以构建输出打印的版本/大小/sha256 为准。

* **方法 A（推荐）**：用数据线把 APK 复制到手机的「下载」文件夹；或通过你信任的网盘 / 邮件 / 聊天工具传到手机。
* **方法 B**：电脑开着 USB 调试时，用一条命令安装（见 [docs/install.md](docs/install.md#方法-b用-adb-安装可选适合开发者)）。

> 升级：直接用同一签名（本项目 `keystore/release.jks`）构建的新版 APK 覆盖安装即可。
> * **v0.1.0 → v0.2.0**：会多一步自动迁移——旧「每台主机粘贴的私钥」迁入密钥库，数据不丢；
> * **v0.2.0 → v0.2.1**：无数据迁移变化，只是多了 token 预校验行为；
> * **v0.2.1 → v0.2.2**：无数据迁移变化；新增「附加 token」开关，旧主机默认勾选（保持原有行为）；
> * **v0.2.2 → v0.2.3**：无数据迁移变化；行为变化——勾选附加 token 时改为「token 交接对话框」
>   （复制网址 + 浏览器地址栏粘贴），解决 Android 浏览器 401 问题（该对话框已被 v0.2.4 删除）；
> * **v0.2.3 → v0.2.4**：**无数据迁移变化**；行为变化——**新主机默认不勾选「附加 token」= 用 App 内置 WebView
>   全自动打开**；已存在主机**保留原来的开关值**（升级后仍按原行为：勾选 = 复制+浏览器粘贴）。v0.2.5 起该开关被
>   删除，已有主机的开关值不再生效（见下一条）。
> * **v0.2.4 → v0.2.5**：**无数据迁移变化**；同一 keystore 覆盖安装，主机/凭证/密钥库/信任表保留。行为变化——
>   每主机的「打开时在网址中附加 token」开关被**删除**，打开方式改为「更多」→「设置」里的全局开关
>   **「通过外部浏览器连接」**（默认关闭 = 内置 WebView）；旧主机统一按全局默认走内置页面。
>   设置页另新增「自动收起内置页面的顶部横栏」（默认开启）。
> 详见 [docs/install.md §7](docs/install.md#7-升级覆盖安装与数据保留)。

### 2. 允许安装未知应用并安装（手机上操作）

1. 在手机上用「文件管理」打开刚传过去的 `dsh-remote-hosts-<版本>.apk`。
2. 系统提示「禁止安装未知应用」时，点**设置**，打开**允许来自此来源的应用**，再返回继续安装。
   （不同品牌路径略有差异，见 [docs/install.md](docs/install.md#2-允许安装未知应用)）
3. 点**安装** → **完成** → 在桌面/应用列表里找到 **「DSH 远程主机」**。

### 3. 导入 SSH 配置（手机上操作）

1. 打开 App，点右上角 **「更多」（⋮）** → **导入 SSH 配置**。
2. 把电脑上 `~/.ssh/config` 的内容**粘贴**到输入框（或点「选择文件…」选一个 `config` 文件）。
3. 点 **解析预览**，确认识别出的主机数量无误，点 **导入 N 台主机**。
4. 看到 **「SSH 配置里的 IdentityFile 无法在手机上直接读取…」** 是正常的：手机读不到电脑上的私钥文件。
   **v0.2.0 起你不需要逐台粘贴私钥**——下一步在密钥管理里生成/导入一把，然后在主机里选择它即可。

### 4. 生成或导入 SSH 密钥（手机上操作，一次就够）

1. 点右上角 **「更多」（⋮）** → **SSH 密钥管理…**。
2. 点 **生成新密钥**：起个名字（默认 `app-key-1`），RSA 位数保持默认 **3072**，点生成。
3. 生成完成后会显示**公钥全文**，点 **复制公钥**。
4. 在**远端机器**上把公钥追加到 `~/.ssh/authorized_keys`（命令见 [§8](#8-ssh-密钥管理推荐)），
   或者把公钥交给服务器管理员。
5. 如果你已经有一把想复用的密钥（比如专门为手机准备的），点 **导入密钥对**：粘贴私钥、按需填口令、
   可粘贴公钥做配对校验。

> 已有旧版（v0.1.0）主机数据？不用手动做任何事：升级后首次打开 App 会把旧的「内联私钥」自动
> 迁入密钥库并按内容去重，主机自动指向迁移后的密钥。详见 [docs/install.md §7](docs/install.md#7-升级覆盖安装与数据保留)。

### 5. 编辑主机：选择密钥 + 填 DSH 凭证（手机上操作）

1. 在主机列表中，点目标主机那一行的 **编辑**。
2. **SSH 认证方式** 选「密码」或「私钥」：
   * 密码：直接输入 SSH 登录密码。
   * 私钥：在 **密钥** 下拉框里选择第 4 步生成/导入的密钥（会显示名称 + 指纹缩略）；
     列表为空时点旁边的 **管理 SSH 密钥…** 去生成/导入。
3. **跳板机（可选）**：SSH 配置里有 `ProxyJump` 的话导入时已带上；也可手动填 `user@192.0.2.10:22`
   或**列表里另一台主机的别名**。
4. **访问方式**：保持 **SSH 隧道（推荐）**。
5. **DSH 凭证**：粘贴第 0 步拿到的 `http://127.0.0.1:<端口>/?token=<令牌>`。
6. **打开方式不在编辑页设置**：v0.2.5 起每主机的「打开时在网址中附加 token」开关已**删除**，改为全局设置——
   主页 **「更多」（⋮）→「设置」** 里的 **「通过外部浏览器连接」**（默认关闭 = App 内置 WebView 全自动打开）。
   编辑页只保留一行提示指向设置页；两种方式的区别见 [§4.1](#41-v024-的两种打开方式)。
7. 点 **保存**。回到列表后该主机应显示 **「已配置」**。

> 编辑已有主机时：凭证输入框会提示「已保存：端口 N，token abc…xyz（留空保持不变）」；
> 密钥下拉框会预选该主机已用的密钥。不想改就留空/不改，直接保存。

### 6. 点「打开」→ 自动打开（手机上操作）

1. 点该主机的 **打开**，状态变成 **「连接中…」**。首次连接会弹出 **确认 SSH 主机密钥**：
   在远端用 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` 核对指纹，一致就点 **信任并连接**。
2. 首次使用会申请**通知权限**（Android 13+）——允许它，隧道在后台时有常驻通知可「全部断开」；拒绝也能用。
3. 隧道建立后，按**设置页**「通过外部浏览器连接」开关（默认关闭）走两条不同的路：
   * **关闭（默认，v0.2.5 推荐）**：App 自动启动内置 WebView：先经隧道用 token 交换登录 cookie、
     注入 WebView，再加载**不含 token** 的 `http://127.0.0.1:<隧道端口>/`。你会看到很短的进度条，
     然后就是远端 DSH UI（WebSocket 实时更新也在 App 内）。失败时 App 显示错误面板
     （**去编辑凭证 / 重试 / 关闭**），见
     [docs/troubleshooting.md §7.2](docs/troubleshooting.md#72-模式-bwebview失败面板与排查)。
   * **开启（外部浏览器模式）**：**没有任何对话框**。App 先在隧道内**预校验 token**（失效会提示「远端拒绝了 token…」，
     此时不会复制网址、不会打开浏览器）；校验通过后把完整网址
     `http://127.0.0.1:<隧道端口>/?token=…` **原封不动**复制到敏感剪贴板，并打开**默认浏览器首页**，
     同时 Toast「网址已复制，请在浏览器地址栏粘贴打开」。到浏览器**地址栏长按 → 粘贴 → 打开**即可登录
     （浏览器随后跳到干净地址）。不想现在打开浏览器也没关系：网址仍在剪贴板里，随时粘贴。
     此时也可用长按主机菜单的 **「复制打开网址（含 token）」**（隧道已打开时可用）重新复制。
4. 隧道保持打开期间（通知栏有常驻通知）页面才能继续加载/更新；点「全部断开」后需要重新「打开」
   （本地端口可能变化：外部浏览器模式要重新复制粘贴；内置页面重新打开即可）。

> **为什么默认用内置 WebView？** Android 浏览器会把「由其他 App 发起、且经过 303 跳转」的导航当作 cross-site，
> 拦截远端 `dsh web` 设置的 `SameSite=Strict` 登录 cookie（Chrome/Firefox/Edge 都一样）→ 外部浏览器里显示
> `authentication required`。v0.2.4 起的对策是：**默认不用外部浏览器**，改由 App 自己的 WebView 完成登录
> （App 自己请求 token 交换、自己注入 cookie，没有「跨 App 导航」问题）；需要外部浏览器时，让**你**在地址栏
> 粘贴网址（属于用户发起的导航，不受限制）。v0.2.5 把「用哪个载体」升级为全局设置。详见
> [docs/troubleshooting.md §7.5](docs/troubleshooting.md#75-samesite-根因与-v024-的两种方式)。

## 4. 如何获取 DSH 凭证 URL

在**远端主机**上（不是手机上）操作：

1. 登录远端机器，确认 `dsh web` 正在运行（或按你们平时的方式启动它）。
2. 从 `dsh web` 的启动输出里找到类似下面的一行，**整行复制**：

   ```text
   http://127.0.0.1:<端口>/?token=<令牌>
   ```

3. 把这条 URL 粘贴到 App 的主机编辑页「DSH 凭证」一栏。

注意：

* URL 里的 `127.0.0.1:<端口>` 是**远端自己的回环地址**，手机访问不到它——App 会用 SSH 隧道把这个端口搬到手机本地，
  再由 **App 内置 WebView（默认）** 或**外部浏览器（设置页开启「通过外部浏览器连接」后）** 打开。
* 粘贴 `http(s)://` 开头的完整地址即可；App 只取 **端口** 和 **token** 两个信息。
* **令牌就是密码**：不要把它发到群里、不要写进文档或截图。远端重启 `dsh web` 后 token 通常会变化，旧凭证会失效。
* **token 失效时**：**外部浏览器模式**下 App 会在打开前预校验 token，直接提示「远端拒绝了 token…」且不会打开浏览器；
  **内置 WebView** 的 token 交换会失败，显示错误面板（**去编辑凭证 / 重试 / 关闭**）。
  按 [docs/troubleshooting.md §7](docs/troubleshooting.md#7-打开异常webview-失败--401--authentication-required)
  里的步骤，用远端**最新**打印的 URL 覆盖「DSH 凭证」即可（编辑时留空会保留旧 token，必须粘贴新 URL）。

### 4.1 v0.2.4 的两种打开方式

> **v0.2.5 起选择方式变了**：两种路径本身保留（下表），但「走哪条」不再由每台主机的复选框决定，
> 而是由主页 **「更多」（⋮）→「设置」→「通过外部浏览器连接」** 这个**全局开关**决定（默认关闭 = 内置 WebView）。
> 旧主机的每主机开关值不再生效；编辑页只显示一行提示指向设置页。

| | **内置 WebView（默认：全局开关关闭）** | **外部浏览器（全局开关开启）** |
|---|---|---|
| 点「打开」后 | **无对话框**，App 自动在**内置系统 WebView** 里打开远端 DSH UI | **无对话框**，App 复制完整网址到敏感剪贴板 + 打开默认浏览器首页 + Toast 提示 |
| 浏览器 | **不打开外部浏览器** | 打开**默认浏览器首页**（不是目标网址） |
| token 交换 | App 自己经隧道请求 `/?token=…`，拿到 `dsh-auth-*` cookie 后注入 WebView | 由你在浏览器地址栏粘贴，浏览器自己完成 token 交换 |
| 实际加载的地址 | `http://127.0.0.1:<隧道端口>/`（**不含 token**） | `http://127.0.0.1:<隧道端口>/?token=…`（由你粘贴） |
| 你需要做什么 | 只需点「打开」 | 点「打开」→ 到浏览器**地址栏粘贴** → 打开 |
| 失败时 | WebView 显示错误面板：**去编辑凭证 / 重试 / 关闭** | App 提示「远端拒绝了 token…」（token 失效）或「无法打开浏览器」 |
| 适合场景 | 日常使用（默认推荐） | 想用自己熟悉的浏览器、或需要浏览器插件/书签时 |

**内置 WebView 的操作（默认，3 步）**：确认设置里「通过外部浏览器连接」**关闭** → 点「打开」→ App 在后台完成
token 交换和 cookie 注入后直接显示远端 DSH UI；顶部细进度条走完即可操作，WebSocket 实时更新也在 App 内。

**外部浏览器模式的操作（4 步）**：设置里**开启**「通过外部浏览器连接」（会弹一次安全告警）→ 点「打开」→
App 复制完整网址并打开浏览器首页后，在浏览器**地址栏长按 → 粘贴 → 打开**。
成功后会看到远端 DSH UI（浏览器随后跳到干净地址）。

**为什么外部浏览器模式不能让 App 直接跳转？** Android 浏览器把「外部 App 发起 + 303 跳转」判定为 cross-site，
拦截 `SameSite=Strict` 登录 cookie（Chrome/Firefox/Edge 都受影响），所以 App 直接打开带 token 的网址会 401；
而**地址栏粘贴是你自己发起的导航**，浏览器会正常完成登录握手。**内置 WebView 则完全绕开了这个问题**：
登录由 App 自己的 WebView 完成，不存在「跨 App 导航」。

其他说明：

* 两种方式的登录状态**互不相通**：内置 WebView 的 cookie 存在 App 的 WebView cookie 里，外部浏览器的 cookie 存在你的
  浏览器里；切换方式后需要让新载体重新登录一次（内置 WebView 点「打开」会自动做，外部浏览器粘贴一次即可）。
* **切换方式**：主页「更多」（⋮）→「设置」→ 切换「通过外部浏览器连接」，**立即生效**（下一次点「打开」生效），
  不会修改已保存的凭证。
* 隧道保持打开期间页面才能加载；**关闭隧道后重开，本地端口可能变化**，外部浏览器模式需要重新点「打开」→ 复制 → 粘贴，
  内置 WebView 重新点「打开」即可（每次都会重新注入 cookie）。
* 长按主机菜单里的 **「复制打开网址（含 token）」** 仍保留（隧道已打开时可用），可作为「先复制、稍后再粘贴」的
  入口（外部浏览器模式的备用手段）；复制出的网址含 token，粘贴完请清空剪贴板。
* 设置页的「通过外部浏览器连接」开关旁有 **?** 按钮：随时点开可看两种方式的说明与安全告警；
  **开启**时会自动弹一次告警（token 会复制到剪贴板）。
* 完整排障与原理见
  [docs/troubleshooting.md §7](docs/troubleshooting.md#7-打开异常webview-失败--401--authentication-required)，
  设置相关常见问题见 [docs/troubleshooting.md §16](docs/troubleshooting.md#16-设置页与打开方式v025)。

## 5. 如何把电脑上的 SSH config 弄到手机

手机上的 App **无法直接读取电脑的 `~/.ssh/config`**，需要你「搬」一份文本过去：

### 方法 A：复制粘贴（最简单）

1. 电脑上用记事本 / VS Code 打开 `~/.ssh/config`（Windows 路径一般是 `C:\Users\<你的用户名>\.ssh\config`）。
2. `Ctrl+A` 全选、`Ctrl+C` 复制。
3. 用你信任的方式把这段文本传到手机（微信「文件传输助手」、邮件草稿、备忘录同步等）。
4. 在手机上打开 App → **「更多」（⋮）→ 导入 SSH 配置** → 粘贴 → **解析预览** → 导入。

### 方法 B：传一个文件

1. 把 `config` 文件传到手机（数据线 / 网盘 / 聊天工具）。
2. App 里 **「更多」（⋮）→ 导入 SSH 配置** → **选择文件…** → 选中该文件 → **解析预览** → 导入。

### 注意事项

* 配置里的 `Include` 指令在手机上无法展开：App 会给出警告，这些被 include 的主机不会出现在预览里。可以把被 include 的文件内容合并进同一份 config 再导入。
* 配置里的 `IdentityFile` 只是**提示信息**，手机读不到电脑上的那个文件。**v0.2.0 起请在「SSH 密钥管理」里生成或导入密钥**，再到主机编辑页选择；不要（也不需要）把私钥粘贴到每台主机里。
* 如果你习惯在手机上的 **Termux** 里管理 SSH（已经有 `~/.ssh/config` 和私钥），Termux 的 `~/.ssh` 属于
  Termux 应用，本 App 无法直接读取；**推荐做法是不共用私钥，直接在 App 内生成一把新密钥**，把它的公钥
  装到远端即可（见 [§8](#8-ssh-密钥管理推荐)）。若确需迁移 Termux 里的私钥，见
  [docs/install.md §4 补充](docs/install.md#补充从-termux--已有-ssh-配置迁移可选进阶) 和进阶文档
  [docs/android-ssh-guide.md](docs/android-ssh-guide.md)。

## 6. 安全与隐私（务必读一遍）

* SSH 密码、**App 生成的 SSH 私钥**、DSH token **加密保存**在 App 私有目录（Android Keystore 生成的不可导出密钥 + AES-256-GCM），`allowBackup=false`，不参与系统备份。
* **私钥只在 App 内**：App 内生成的密钥对，私钥永远不会交给浏览器/其他 App；你只会把**公钥**复制出去装到远端。公钥可以公开，不算秘密。
* token **只会**出现在 App 内部构造的网址/请求里：内置 WebView 的 token 交换请求（App→远端，**WebView 实际加载的网址不含 token**）；
  设置页开启「通过外部浏览器连接」时 App 复制到剪贴板并（由你粘贴到）浏览器地址栏的那条 URL；以及隧道内的一次 token 预校验请求
  （仅外部浏览器模式）。App 不写日志、不写通知、不把 token 存进明文配置文件。
* **设置页只保存两个布尔值**（SharedPreferences 文件 `settings`，未加密但**不存任何凭证**：没有 token/密码/私钥/URL）。
* **内置 WebView 的安全边界**：只加载 `http://127.0.0.1:<隧道端口>/`（其他 http(s) 外链交给系统浏览器）；关闭
  file/content 访问与混合内容；App 只向**自己的 WebView**注入 `dsh-auth-*` 登录 cookie，
  **绝不把 cookie 交给外部浏览器**（外部浏览器也从未收到过 cookie）。
* **外部浏览器模式会把含 token 的完整网址放进系统剪贴板**（敏感内容，Android 13+ 带敏感标记）。粘贴到浏览器后 token 可能进入
  浏览器历史；**打开成功后请清空剪贴板**，不要把该网址转发/截图。开启该开关时设置页会弹一次告警。
* 首次连接任何主机都需要你**人工确认主机密钥指纹**；以后若指纹变化会拒绝连接（可能是换机器，也可能是中间人攻击）。
* 卸载 App 会**同时删除所有已保存的凭证与密钥**（Keystore 密钥随之失效），重装后需要重新录入。
* 手机丢失时：在远端 `~/.ssh/authorized_keys` 里删掉这台手机的公钥，并重启远端 `dsh web` 更换 token。

完整威胁模型、密钥生命周期和「推荐做法」见 **[docs/security.md](docs/security.md)**。

## 7. 已知限制（别踩坑）

* **v0.2.5 变更（重要）**：打开方式改为**全局设置**，且**不再有任何「App 直接把隧道网址交给浏览器」的路径**
  （「直接网址」模式除外）：
  * **设置页「通过外部浏览器连接」关闭（默认）**：App 使用**内置系统 WebView 全自动打开**，
    不经过外部浏览器；token 交换与 cookie 注入都由 App 在隧道内完成，WebView 加载的网址不含 token。
  * **开启（外部浏览器模式）**：点「打开」后**无对话框**——App 复制完整含 token 网址到敏感剪贴板并打开浏览器首页，
    你需要到**地址栏粘贴**打开。v0.2.3 的「token 交接」对话框与「直接打开/取消」按钮已全部删除。
  * 旧主机的每主机开关值不再生效，统一跟随全局开关；想改回内置页面，到设置页关掉该开关即可。
  * 详见 [§4.1](#41-v024-的两种打开方式) 与
    [docs/troubleshooting.md §7](docs/troubleshooting.md#7-打开异常webview-失败--401--authentication-required)。
* **内置 WebView 顶部横栏收起（v0.2.5）**：自动收起依赖系统 WebView 上报滚动事件
  （`View.OnScrollChangeListener`）。个别 ROM 若不触发该回调，自动收起不会生效，但右侧「收起」按钮与
  点按收起后的横栏仍可手动操作；收起状态**不持久化**（每次打开都是展开态）。这是纯 UI 层特性，
  **真机表现仍待用户确认**（见 [docs/troubleshooting.md §16.3](docs/troubleshooting.md#163-内置页面横栏不自动收起)）。
* **内置 WebView 的边界**：依赖手机系统的 **Android System WebView**（或 Chrome 提供的 WebView 实现）；
  系统组件太旧/被停用时可能加载失败（见排障 §7.2）。App 内打开的页面**不会**与系统浏览器的书签/登录/插件共享；
  切到后台后 WebSocket 实时更新可能暂停，回前台一般会自动恢复，仍不更新就退出该页面重新「打开」。
* **两种方式的登录状态互不相通**：WebView 的 cookie 与系统浏览器的 cookie 是两套；切换方式后需要让新载体重新登录
  （内置 WebView 每次打开自动交换 cookie；外部浏览器粘贴一次即可）。
* **外部浏览器模式的 token 会短暂出现在浏览器地址栏/历史**：远端 `GET /?token=` 换 cookie 后 303 跳转，这是远端自身的
  登录机制（桌面端一样）；token 还会先经过一次系统剪贴板（App 有敏感标记 + 设置页告警），粘贴完请清空剪贴板。
  内置 WebView 不涉及外部浏览器地址栏/历史。
* **没有 Play Store / 应用商店上架，也没有自动更新**：升级靠手动下载新 APK 覆盖安装；必须用**同一个签名 keystore** 构建的 APK 才能覆盖（否则要先卸载、数据会丢）。
* **未在真机上做完整验收**：本项目在无 Android 设备的环境里构建，v0.2.5 已通过编译检查、**415 项 JVM 单测**、真实 SSH 测试和 **76/76 APK 静态校验**；UI（尤其是新的横栏收起）仍需你真机确认，步骤见 [docs/install.md §9](docs/install.md#9-真机首次验收清单可选但建议做一遍)。
* **不做自动重连**：切网络、休眠、隧道被踢掉后，回 App 再点一次「打开」即可重连。
* **部分手机的省电策略会杀后台**：需要把本 App 设为「无限制电量 / 允许后台运行」，隧道才能更稳。
* **手机必须能访问 SSH 主机**：如果主机只在校园网/公司内网可见，手机需要连对应 Wi-Fi 或 VPN。
* **密钥兼容性**：App 内生成的密钥是 **RSA**（2048/3072/4096，默认 3072），兼容性最好；导入的
  **ed25519** 密钥能否使用取决于手机系统的加密实现（部分旧 Android 不支持），建议优先 RSA 或 ECDSA。
* **不支持 Android 8.0 以下版本**（minSdk 26），目标 SDK 为 35。

### 未实现 / 后续可能（roadmap）

以下是**当前版本（0.2.x）不支持**的方向，仅说明设计取向——请不要按"已支持"使用：

* **接收其他 App 的"分享"**（`ACTION_SEND`）来导入 config / 公钥，例如从 Termux 用
  `termux-open --send` 直接把文件发给本 App。
* **用 SAF 目录授权**（`ACTION_OPEN_DOCUMENT_TREE`）直接导入 Termux 的 `~/.ssh`：
  Termux 官方提供 SAF 文档提供器，用户需要先在 Termux 里把 `~/.ssh` 软链接到非隐藏目录
  （例如 `ln -s ~/.ssh ~/dsh_ssh`），再在文件选择器里授权该目录。
* **密钥的导出 / 二维码**：当前可以在详情页复制公钥文本（已支持），但还不能把公钥导出为文件或生成二维码。
* **Phase-2 本地反向代理**：在隧道之上再起一个本地 HTTP 反代，把 token 从浏览器 URL 中彻底移除
  （桌面插件 `dsh-remote-hosts` 的 `docs/web-proxy-plan.md` 有完整思路；本 App 的
  `CredentialUrl.browserUrlFor()` 是唯一 URL 出口，将来只改这一个函数即可）。**内置 WebView 路径已经实现
  「App 内自动登录、WebView 地址不含 token」的日常体验**；设置页开启「通过外部浏览器连接」时仍是 URL 携带 token
  的方案；要在外部浏览器里也彻底去掉 token，仍需 P2 反代。详见
  [docs/security.md §4](docs/security.md#4-token-的出口与-webview-安全边界)。

## 8. SSH 密钥管理（推荐）

### 8.1 为什么用 App 自己生成/管理的密钥

* **每台设备、每个 App 一把独立密钥**：手机丢失或卸载 App 时，只要吊销这一把公钥，不影响电脑上的密钥。
* **不碰电脑上的私钥**：不用把 `~/.ssh/id_rsa` 复制到手机里，减少私钥在聊天软件/网盘/剪贴板里留痕的风险。
* **主机只存引用**：主机编辑页选择密钥，多台主机可以共用同一把密钥；密钥轮换时只改一处。
* **统一加密存储**：密钥与主机凭证在同一个 AES-256-GCM 加密文件里（Keystore 保护）。

### 8.2 生成新密钥（推荐路径）

1. App 内 **「更多」（⋮）→ SSH 密钥管理… → 生成新密钥**。
2. 填写名称（默认 `app-key-1`），选择 RSA 位数（**2048 / 3072（默认）/ 4096**）。
3. 生成完成后，对话框里会显示**公钥全文**，点 **复制公钥**。
4. 到**远端机器**执行（把公钥粘贴到 `~/.ssh/authorized_keys`）：

   ```bash
   # 远端机器上（先在 home 目录；authorized_keys 不存在就创建）
   mkdir -p ~/.ssh && chmod 700 ~/.ssh
   # 把 App 里复制的公钥整行粘贴到下面命令的双引号里（示例以 ssh-rsa AAAA... app-key-1 开头）
   echo "ssh-rsa AAAA... app-key-1" >> ~/.ssh/authorized_keys
   chmod 600 ~/.ssh/authorized_keys
   ```

   也可以直接用文本编辑器把公钥追加到 `~/.ssh/authorized_keys`，注意**必须是一整行**、不要断行。
5. 回到 App 主机编辑页，**密钥**下拉框选它即可。

> 建议给 App 生成的密钥起可识别的名字（如 `pixel-dsh`），方便以后在服务器上吊销/审计。

### 8.3 导入已有密钥对

* 在 **SSH 密钥管理… → 导入密钥对** 里粘贴私钥（PEM 或 OpenSSH 格式），有口令就填口令。
* **可选**粘贴对应的公钥行：App 会校验公钥与私钥是否匹配，不匹配直接拒绝（不会保存）。
* 导入的私钥同样进入加密存储；导入后删除你手机上的临时私钥文件、清空剪贴板。
* 兼容性：RSA / ECDSA 一般可用；**ed25519 取决于手机系统实现**，部分旧系统无法用于连接。
  不确定就用 App 生成的 RSA 密钥。

### 8.4 查看 / 复制 / 删除

* 密钥列表显示：名称、类型、指纹（`SHA256:…`）、创建时间、**被 N 台主机使用**。点一行看详情。
* 详情页可以 **复制公钥**（安全，可公开）；**私钥默认隐藏**，点「显示私钥」需二次确认，
  「复制私钥」会提示敏感信息风险（复制后请尽快清空剪贴板）。
* 删除密钥前会提示被多少台主机引用：**删除后这些主机将无法用私钥登录**，需要重新生成/导入密钥并在主机中重新选择。
* 指纹可用于和服务器核对：在远端执行 `ssh-keygen -lf ~/.ssh/authorized_keys`，找 `SHA256:` 开头的指纹，
  与 App 密钥详情里显示的**直接比较**即可（格式一致：`SHA256:<标准 base64>`、无 `=` 填充）。

### 8.5 从 v0.1.0 升级的自动迁移

* v0.1.0 保存的是「每台主机内联私钥」。升级到 0.2.0 后第一次打开 App 时：
  * 每把**不同的**私钥会变成一个密钥库条目（内容相同的私钥只建一条）；
  * 主机自动指向迁移后的密钥（`keyId`），并**清空**原来的内联私钥字段；
  * 迁移结果立即写入加密存储，**幂等**（重复打开不会重复迁移）；
  * 如果某把旧私钥的格式/口令导致无法解析，该主机会**保留旧的内联私钥继续可用**（不丢数据），
    但不会出现在密钥库里；建议之后到主机编辑页重新生成/导入密钥并改选。
* 迁移后建议打开 **SSH 密钥管理**，给自动迁移的密钥改个可读名称，并核对指纹。
* 迁移不会改变主机名/端口/凭证等其它字段，升级后「打开」应和以前一样可用。
* **v0.2.0 → v0.2.1 无数据迁移**：直接覆盖安装即可，主机/凭证/密钥库原样保留，只是打开前多了
  token 预校验（失效时 App 直接提示而不是打开 401 页面）。
* **v0.2.1 → v0.2.2 无数据迁移**：直接覆盖安装即可；旧主机默认按「附加 token」处理（与原来行为一致）；
  v0.2.4 起「取消勾选」= App 内置 WebView 自动打开；v0.2.5 已删除该开关，统一走全局设置（见下两条）。
* **v0.2.2 → v0.2.3 无数据迁移**：直接覆盖安装即可；主机/凭证/密钥库原样保留（该版本的「token 交接」对话框
  已在 v0.2.4 中被新的 A/B 打开方式取代）。
* **v0.2.3 → v0.2.4 无数据迁移**：直接覆盖安装即可；主机/凭证/密钥库/信任表原样保留。行为变化：
  * **新添加的主机默认「不附加 token」**= 用 App 内置 WebView 全自动打开；
  * **已有主机保留原开关值**（升级前勾选的就仍是模式 A：复制网址 + 浏览器地址栏粘贴，只是去掉了对话框）；
  * v0.2.5 起该开关被**删除**，已有主机的开关值不再生效（见下一条）。
* **v0.2.4 → v0.2.5 无数据迁移**：同一签名直接覆盖安装即可；主机/凭证/密钥库/信任表原样保留。
  行为变化：打开方式与横栏收起改为「更多」→「设置」里的全局开关；旧主机的每主机开关被忽略，
  **全局默认 = 内置 WebView**（推荐）；编辑页不再有该开关，改为一行指向设置页的提示。
  旧版加密存储里多余的 `appendToken` 字段在解码时被忽略，主机数据正常加载，不需要手动迁移。

## 10. 从源码构建（开发者 / 需要自己改代码时）

只需要 Windows + Node.js，**不需要**安装 JDK / Android Studio / Gradle：

```powershell
# 第一次：下载便携工具链（JDK 17 + Android platform 35 + build-tools 35 + JSch，约 300–400 MB，需要网络）
node tools\setup-toolchain.mjs

# 设置签名密钥密码（仓库不保存密码；第一次构建且 keystore 不存在时用它生成新密钥）
$env:DSH_KEYSTORE_PASSWORD = '<你的 keystore 密码>'

# 构建签名 APK（产物在 dist\）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build.ps1
```

构建原理（为什么没有 Gradle）、签名 keystore、测试命令和版本号修改位置，见 [docs/build.md](docs/build.md)。
