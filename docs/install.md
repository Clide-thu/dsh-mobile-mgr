# 安装、升级与卸载（详细步骤）

本文面向 **Android 开发经验非常有限**的用户。每一步都写清楚「在什么设备上」「点哪里」。
如果你只想最快跑通，先看 [README 的 5 分钟快速开始](../README.md#3-5-分钟快速开始)；遇到问题看
[docs/troubleshooting.md](troubleshooting.md)。

> **v0.2.0 变化**：App 自带 SSH 密钥管理（生成/导入密钥对），主机编辑页改为「选择密钥」，
> 不再需要逐台粘贴私钥。若你从 v0.1.0 升级，旧的私钥会在首次打开时自动迁移，数据不丢
> （见 [§7](#7-升级覆盖安装与数据保留)）。
>
> **v0.2.5 变化（重要）：打开方式改为全局设置 + 内置页面顶部横栏可收起**
> * **设置页**：主页「更多」（⋮）→ **设置**。两个全局开关——**「通过外部浏览器连接」**（默认**关闭** =
>   App 内置 WebView 全自动打开，推荐）与**「自动收起内置页面的顶部横栏」**（默认开启）。开关立即生效并持久化，
>   只保存布尔值，**不保存任何凭证**。
> * **每主机的「打开时在网址中附加 token」开关已删除**（`appendToken` 字段一并移除）：原来勾选/不勾选决定
>   打开方式，现在统一由设置页的全局开关决定；旧主机的选择不再生效（全局默认 = 内置 WebView）。
> * **内置页面顶部横栏可收起**：展开态 56dp（返回 + 标题 + 副标题 + 收起按钮），收起后是 32dp 的一行主机名
>   （点按该行展开）；向下滚动自动收起、滚回顶部自动展开，右侧按钮可随时手动收起。见
>   [§4 第 8 步](#第-8-步看到远端-dsh-ui)。
> * 升级到 v0.2.5 的方法与行为变化见 [§7.7](#77-从-v024-升级到-v025重要行为变化)。
>
> **v0.2.4 变化（历史）**：引入 A/B 两种打开方式，默认在 App 内自动打开；该版本的每主机开关已在 v0.2.5 删除。
>
> 此前版本要点：v0.2.1 打开前 token 预校验；v0.2.2 新增「附加 token」开关与长按「复制打开网址（含 token）」；
> v0.2.3 的 token 交接对话框已被 v0.2.4 取代。

## 1. 安装前的要求

| 项目 | 要求 |
|---|---|
| 手机系统 | **Android 8.0 及以上**（API 26+）；App 的目标版本（targetSdk）为 35 |
| 手机网络 | 能访问你要连的 SSH 主机（同一 Wi-Fi / 校园网 / 公司网 / 已连 VPN） |
| 浏览器 | **默认（内置页面）**：App 内置系统 WebView（Android 系统组件，无需额外安装）；**外部浏览器模式**：任意系统默认浏览器（Chrome、Edge、手机自带浏览器），需在设置页开启「通过外部浏览器连接」 |
| APK | `dist/dsh-remote-hosts-0.2.5.apk`：v0.2.5（versionCode 7），**751845 字节（约 0.72 MB）** |
| 远端 | SSH 可登录；远端已启动 `dsh web` 并拿到 `http://127.0.0.1:<端口>/?token=<令牌>` |
| SSH 密钥 | 推荐在 App 内**生成**一把新密钥（无需提前准备）；也可以导入已有密钥对 |

> 说明：这是**侧载 APK**，没有上架任何应用商店，也没有自动更新。APK 来源不明时不要安装。
> 本次交付产物的 SHA256 是：
>
> ```text
> b6c613b682a093d0aea02edf987fd5a2d2de23a1f1a16cbd53f55d511434a1d9
> ```
>
> 拿到 APK 后可以自己核对（Windows PowerShell，在项目根目录或 APK 所在目录执行）：

> 输出的哈希值与上面一致再安装（`Get-FileHash` 默认输出大写，不区分大小写）。
> 如果你拿到的是自己重新构建的 APK，以构建者给出的 sha256 为准（详见 [docs/build.md §8](build.md#8-产物与分发)）。

## 2. 允许「安装未知应用」

从 Android 8.0 开始，系统不再有全局的「未知来源」开关，而是**按「打开 APK 的那个 App」逐个授权**。
比如你用「文件管理」打开 APK，就授权给「文件管理」；用浏览器下载后直接点开，就授权给浏览器。

### 通用步骤

1. 在手机上用**文件管理**找到 APK 文件（通常在「下载 / Download」文件夹）。
2. 点它。系统弹出 **「为了安全，你的手机不允许安装未知应用」** 之类的提示时，点 **设置**。
3. 在打开的页面里，把 **「允许来自此来源的应用」**（有的系统叫「允许安装未知应用」）打开。
4. 按返回键回到安装界面，点 **安装**。

### 各品牌路径参考（找不到时在设置里搜索「未知」）

| 品牌 / 系统 | 设置路径参考 |
|---|---|
| Google Pixel / 原生 Android | 设置 → 应用 → 特殊应用权限 → 安装未知应用 → 选择来源 App（文件 / Chrome）→ 允许 |
| 小米 / Redmi（MIUI / 澎湃 OS） | 设置 → 应用设置 → 特殊应用权限 → 安装未知应用 |
| 华为 / 荣耀（EMUI / HarmonyOS） | 设置 → 安全 → 更多安全设置 → 外部来源应用下载 → 找到来源 App 允许 |
| OPPO / 一加 / realme（ColorOS） | 设置 → 安全 → 安装外部来源应用 / 外部来源应用 |
| vivo / iQOO（OriginOS） | 设置 → 安全 → 更多安全设置 → 外部来源应用 |
| 三星（One UI） | 设置 → 应用程序 → 特殊访问权限 → 安装未知应用 |
| 其他 | 在「设置」顶部搜索框输入 **未知应用** 或 **安装未知应用** |

### 可能遇到的额外提示

* **Play 保护机制（Play Protect）提示风险**：如果你确认 APK 来源可靠（自己构建或可信的人给的），
  可以选择「仍要安装 / 安装」。不放心就别装。
* **「你的手机不允许安装此应用」且没有设置入口**：可能是公司/学校统一管理的设备（MDM，
  设备管理员策略禁止侧载），这种情况无法绕过，需要换一台自己控制的手机。
* **「应用未安装 / 解析包时出现问题」**：见 [docs/troubleshooting.md](troubleshooting.md#1-安装失败)。

## 3. 安装 APK

1. 点 APK 文件 → **安装**。
2. 等待 1–2 秒，出现 **「应用已安装」** → 点 **打开**（或 **完成** 后回桌面找图标）。
3. 桌面/应用抽屉里的图标名是 **「DSH 远程主机」**（绿色图标）。
4. 第一次打开如果提示 **通知权限**，见本文 [§6](#6-通知权限android-13-及以上)。

### 方法 B：用 adb 安装（可选，适合开发者）

前提：电脑装了 Android SDK Platform-Tools（有 `adb` 命令），手机开启 USB 调试并授权本电脑。

```powershell
# 电脑上，在项目根目录执行
adb devices
adb install -r .\dist\dsh-remote-hosts-0.2.5.apk
```

* `-r` = 覆盖安装并保留数据（必须与已装版本**同一个签名**）。
* 输出 `Success` 即安装成功。
* 手机开启 USB 调试的步骤：设置 → 关于手机 → 连点「版本号」7 次 → 返回设置 → 系统 →
  开发者选项 → 打开「USB 调试」，然后电脑首次执行 `adb devices` 时在手机上点「允许」。

## 4. 首次使用（8 步）

> 建议按顺序做。第 1、2 步在**电脑/远端**做；第 3 步之后在**手机**上做。

### 第 1 步（远端/电脑）：拿到 DSH 凭证 URL

在远端机器上启动或查看 `dsh web`，从输出中找到类似：

```text
http://127.0.0.1:<端口>/?token=<令牌>
```

**整条复制**（先临时放到备忘录/邮件草稿里，待会粘贴到手机）。这条 URL 里的 token 就是访问密码，
不要发到群里或截图分享。远端重启 `dsh web` 后 token 通常会变化。

### 第 2 步（电脑）：准备 SSH 配置（可跳过）

* 如果电脑上有 `~/.ssh/config`：用记事本打开，`Ctrl+A` 全选复制。
  Windows 一般在 `C:\Users\<你的用户名>\.ssh\config`。
* 没有 config：跳过这步，第 5 步选「添加主机」手动填。

> **不需要**把电脑上的私钥传到手机：v0.2.0 推荐在 App 内生成一把**手机专用**密钥（第 4 步）。
> 如果你有专门为手机准备的密钥对想复用，也可以在第 4 步「导入密钥对」。

### 第 3 步（手机）：打开 App，允许通知

1. 点桌面图标打开 **「DSH 远程主机」**。
2. 如果弹出通知权限请求（Android 13 及以上），点 **允许**。
   （允许后隧道运行时通知栏会有「N 台主机已连接」，可以一键「全部断开」；拒绝也能用，见 [§6](#6-通知权限android-13-及以上)。）
3. 首次打开应该看到空列表和 **「导入 SSH 配置」/「添加主机」** 按钮。

### 第 4 步（手机）：导入 SSH 配置（或添加主机）

**导入配置：**

1. 点右上角 **「更多」（⋮）** → **导入 SSH 配置**。
2. 把第 2 步复制的 config 文本粘贴到文本框；
   或点 **选择文件…**，在系统文件选择器里选中传到手机的 `config` 文件。
3. 点 **解析预览**，页面显示「识别到 N 台主机，W 条警告」。
4. 确认列表里有你要的主机，点 **导入 N 台主机**。

**或者手动添加：** 菜单 **「更多」（⋮）** → **添加主机**。

> 警告里出现 **Include**、**IdentityFile** 都属于正常提示：
> * `Include` 的文件在手机上不会自动展开，需要你把它合并进 config 再导入；
> * `IdentityFile` 只是告诉你要用哪个私钥，手机读不到那个文件；v0.2.0 起请在密钥管理里生成/导入，
>   再到主机编辑页选择（不用逐台粘贴私钥内容）。

### 第 5 步（手机）：准备 SSH 密钥（v0.2.0 新流程）

**推荐：让 App 生成一把手机专用密钥（不碰电脑上的私钥）**

1. **「更多」（⋮）→ SSH 密钥管理…**。
2. 点 **生成新密钥**：名称可以用默认的 `app-key-1`（或改成好记的如 `pixel-dsh`），
   RSA 位数保持默认 **3072**（兼容性最好；追求更快生成可选 2048）。
3. 生成完成后会显示**公钥全文**，点 **复制公钥**。
4. 到**远端机器**上把公钥追加到 `~/.ssh/authorized_keys`：

   ```bash
   mkdir -p ~/.ssh && chmod 700 ~/.ssh
   # 把 App 里复制的公钥整行粘贴到下面双引号里（以 ssh-rsa AAAA... 开头）
   echo "ssh-rsa AAAA... app-key-1" >> ~/.ssh/authorized_keys
   chmod 600 ~/.ssh/authorized_keys
   ```

5. 也可以点 **复制公钥** 后发给服务器管理员，让对方帮你加。

**或者：导入已有密钥对**

1. **SSH 密钥管理… → 导入密钥对**。
2. 粘贴私钥内容（PEM / OpenSSH 格式），有口令就填「私钥口令」；
   也可以点 **从文件导入私钥…** 选手机上的私钥文件（没有扩展名也能选）。
3. 如果手里有对应的公钥行，粘贴到「公钥（可选）」里，App 会校验两者是否匹配；
   不填则由私钥自动推导。
4. 保存后回到列表即可使用。**导入完成后请删除手机上的临时私钥文件、清空剪贴板。**

> 不确定选哪种？**用 App 生成**最省事也最安全：私钥从头到尾只在 App 的加密存储里。
> 密钥管理界面的详细说明见本文 [§4.5](#补充ssh-密钥管理界面生成--导入--查看--删除)。

### 第 6 步（手机）：编辑主机，选择密钥 + 填 DSH 凭证

1. 在主机列表中，点目标主机那一行的 **编辑**。
2. **SSH 认证方式** 选「密码」或「私钥」：
   * 密码：直接输入 SSH 登录密码。
   * 私钥：在 **密钥** 下拉框里选择第 5 步生成/导入的密钥（显示名称 + 指纹缩略）。
     列表为空时点旁边的 **管理 SSH 密钥…** 先去生成/导入。
   * **v0.2.0 起编辑页不再有「粘贴私钥内容」输入框**：私钥只存在于密钥库，主机只保存引用。
3. **跳板机（可选）**：如果你的 SSH 配置里有 `ProxyJump`，导入时已经带上了；也可以手动填
   `user@192.0.2.10:22` 这种形式，或填**列表里另一台主机的别名**。
4. **访问方式**：保持 **SSH 隧道（推荐）**。
5. **DSH 凭证**：粘贴第 1 步复制的 `http://127.0.0.1:<端口>/?token=<令牌>`。
   粘贴后输入框下方会实时显示解析出的端口，没有红色错误提示就说明格式对了。
6. **打开方式不在编辑页设置**：v0.2.5 起每主机的「打开时在网址中附加 token」开关已**删除**，改为全局设置。
   编辑页只有一行提示：「打开方式（外部浏览器 / 内置页面）已改为全局设置：请在主页「更多 → 设置」中切换。」
   到主页 **「更多」（⋮）→「设置」** 可切换 **「通过外部浏览器连接」**（默认关闭 = 内置 WebView 全自动打开）。
   两种方式随时可切换，切换立即生效，不需要重新编辑主机。
7. 点 **保存**。回到列表后该主机应显示 **「已配置」**（没有配置凭证会显示「未配置凭证」）。

> **编辑已有主机时**：凭证输入框会提示「已保存：端口 N，token abc…xyz（留空保持不变）」；密钥下拉框会
> 预选该主机已用的密钥。不想改就留空/不改，直接保存。已保存的 token 只会以掩码形式显示，不会明文回显。

> 如果已经有反向代理 / 内网穿透 / Tailscale 的现成 HTTPS 地址，可以把「访问方式」改成
> **直接网址**，在「直接打开的网址」里填该地址，就不需要 SSH 隧道了（建议用 HTTPS）。

### 第 7 步（手机）：点「打开」，确认主机密钥

1. 点该主机的 **打开** 按钮，状态会变成 **「连接中…」**。
2. 首次连接会弹 **确认 SSH 主机密钥**：核对对话框里的 SHA256 指纹。
   在远端机器上执行下面的命令可以查看指纹（把文件名换成你系统里实际存在的 key）：

   ```bash
   ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
   ssh-keygen -lf /etc/ssh/ssh_host_rsa_key.pub
   ```

   两边一致 → 点 **信任并连接**；不一致 → 点 **取消连接**，先查清楚原因（可能连错机器，也可能有中间人）。
3. **token 预校验（仅外部浏览器模式：设置页开启了「通过外部浏览器连接」）**：主机密钥确认通过后，
   App 会经隧道用 token 请求一次远端。
   * 通过 → 继续第 4 步；
   * App 提示「**远端拒绝了 token（可能已失效：dsh web 重启会换新 token）。请在远端重新复制 dsh web 打印的 URL 更新凭证。**」
     → 说明凭证失效/复制错。回列表 → **编辑** → 把远端**最新**打印的 `http://127.0.0.1:<端口>/?token=…`
     粘贴到「DSH 凭证」→ 保存（**留空会保留旧 token，必须粘贴新 URL 覆盖**）→ 再点「打开」。
     详细排查见 [docs/troubleshooting.md §7](troubleshooting.md#7-打开异常webview-失败--401--authentication-required)。
4. 隧道建立后按设置页的全局开关继续：
   * **关闭（默认，内置 WebView）**：App 自动启动内置 WebView 完成 token 交换并加载页面，直接进入第 8 步，
     **不需要你粘贴任何东西**。交换失败时 WebView 会显示错误面板（**去编辑凭证 / 重试 / 关闭**），
     见下文「补充：App 内置 WebView 的说明」。
   * **开启（外部浏览器模式）**：**没有对话框**——App 把完整 `http://127.0.0.1:<端口>/?token=…`（**原封不动**）
     复制到敏感剪贴板，打开**默认浏览器首页**，并 Toast「网址已复制，请在浏览器地址栏粘贴打开」；
     到浏览器**地址栏长按 → 粘贴 → 打开**即可登录（这一步必须做，否则看不到 UI）。
     若浏览器没有被打开：手动打开任意浏览器粘贴即可（v0.2.4 起不再回退为「直接打开网址」）。
     原因：Android 浏览器会拦截「外部 App 发起 + 303 跳转」的 SameSite=Strict cookie，
     地址栏粘贴属于用户发起导航，可正常登录。详见
     [docs/troubleshooting.md §7](troubleshooting.md#7-打开异常webview-失败--401--authentication-required)。
5. 如果 25 秒内没有连上，App 会提示连接超时，可直接看 [docs/troubleshooting.md](troubleshooting.md)。

> 主机密钥只会在**第一次**连接时询问；以后如果该主机的密钥发生变化，App 会**拒绝连接**并提示
> 「主机密钥已变更」。确认是管理员换过密钥后，可以在编辑页点 **重置此主机的密钥信任**，或菜单
> **「更多」（⋮）→ 已信任的主机密钥… → 清除全部信任** 后重连。
>
> **用了跳板机（ProxyJump）时**会分别确认两次：先确认**跳板机**的指纹，连接建立后再确认**目标主机**的指纹。
> 两次都要核对。跳板机的认证材料沿用目标主机的密码/私钥（当前版本限制）；**不支持逗号分隔的多级跳板**。

### 第 8 步：看到远端 DSH UI

**内置页面（默认，设置页「通过外部浏览器连接」关闭）**：隧道建立后 App 自动进入 WebView 页面，顶部细进度条走完
就能看到远端 DSH 的界面，可直接操作；WebSocket 实时更新也在 App 内生效。之后：

* **顶部横栏收起（v0.2.5）**：设置页「自动收起内置页面的顶部横栏」默认开启。展开态 56dp（返回箭头 + 标题 +
  副标题 + 右侧「收起」按钮）；向下滚动超过约 12dp 后自动收起为一行 32dp 的主机名，**不覆盖页面内容**；
  滚回页面顶部（约 4dp 以内）自动展开；向上滚动不会自动展开（避免和手动收起打架）；点按收起后的横栏可随时展开；
  右侧「收起」按钮可随时手动收起。错误面板出现时会自动展开。收起状态不持久化，每次打开都是展开态。
  在设置页关掉该开关后：横栏始终 56dp、无「收起」按钮、也不自动收起。
* **返回键**：先返回 WebView 内的上一页；没有上一页时退出 WebView 回到主机列表（隧道保持，可再次「打开」）。
  收起态没有返回箭头，点按横栏展开后即可使用，或直接按系统返回键（逻辑不变）。
* **页面里的外部 http(s) 链接**：交给系统浏览器打开（不在 App 内继续）；
* **错误面板**（token 失效 / 无法读取远端响应 / 远端未返回登录 cookie）：按面板提示点
  **去编辑凭证 / 重试 / 关闭**，见
  [docs/troubleshooting.md §7.2](troubleshooting.md#72-模式-bwebview失败面板与排查)；
* 想改用外部浏览器：到主页 **「更多」→「设置」** 开启「通过外部浏览器连接」→ 回到列表重新「打开」。

**外部浏览器模式（设置页开启后）**：App 复制网址并打开浏览器首页后，**在地址栏长按 → 粘贴 → 打开**；
页面会先带 token 加载一次，再跳到干净的地址——看到远端 DSH 的界面就成功了。

此时通知栏应有 **「DSH 远程主机」** 常驻通知；点通知里的 **全部断开**，或 App 菜单 **「更多」（⋮）→ 全部断开**，
可以关闭所有隧道。

如果打开后显示 `authentication required` / 401：

* **内置页面**：通常是 token 失效/不对 → 在错误面板点「去编辑凭证」更新；也可能是隧道已断 → 重新「打开」；
* **外部浏览器模式**：先确认你是通过 **地址栏粘贴** 打开的（不要点旧书签/旧标签；v0.2.4 起已无「直接打开」按钮）——
  Android 浏览器对「外部 App 发起 + 303 跳转」会拦截 SameSite=Strict cookie；
* 确认粘贴的是**完整网址**（含端口 + `?token=…`），且是**本次隧道**的端口（隧道重开后端口会变）；
* token 本身失效时按
  [docs/troubleshooting.md §7](troubleshooting.md#7-打开异常webview-失败--401--authentication-required) 更新凭证
  （编辑时**必须粘贴新 URL 覆盖**，留空会保留旧 token）。

### 补充：App 内置 WebView 的说明

v0.2.5 默认不打开外部浏览器，而是在 App 里用一个系统 WebView 显示远端 DSH UI：

* **需要额外安装吗？** 不需要。WebView 是 Android 系统组件（由 **Android System WebView** 或 Chrome 提供），
  随系统/应用商店更新；如果系统里 WebView 被停用或过旧，内置页面会加载失败
  （处理见 [docs/troubleshooting.md §7.2](troubleshooting.md#72-模式-bwebview失败面板与排查)）。
* **登录怎么完成？** App 经 SSH 隧道用你的 token 请求一次远端，拿到 `dsh-auth-*` 登录 cookie 后，
  只注入 **App 自己的 WebView**，再加载**不含 token** 的 `http://127.0.0.1:<端口>/`。全程不需要你粘贴。
* **cookie 存在哪？** 存在 App 自己的 WebView 存储里，与系统浏览器（Chrome/Edge 等）的登录状态**互不相通**；
  每次「打开」App 都会重新交换一次 cookie，所以隧道端口变化也不用重新登录。
* **安全边界**：只允许 `127.0.0.1:<隧道端口>` 的页面在 WebView 内导航，其他 http(s) 外链交给系统浏览器；
  file/content 访问与混合内容关闭；App 不向外部浏览器传递任何 cookie。
* **与桌面端一致**：这和你在电脑浏览器里打开同一个远端 DSH UI 的信任模型相同（页面代码来自远端，
  不是从 App 分发的）。

### 补充：设置页（v0.2.5，两个全局开关）

入口：主页右上角 **「更多」（⋮）→「设置」**。设置页有两个开关，**修改后立即保存，并在下一次点「打开」时生效**；
不需要重启 App，也不需要重新编辑主机。设置文件只保存布尔值，**不保存任何密码、token 或密钥**。

| 开关 | 默认 | 打开时的效果 | 关闭时的效果 |
|---|---|---|---|
| **通过外部浏览器连接** | **关闭** | 点「打开」后把含 token 的完整网址复制到敏感剪贴板 + 打开默认浏览器首页，由你在地址栏粘贴 | 点「打开」后用 App 内置 WebView 全自动登录并显示 DSH UI（**推荐**） |
| **自动收起内置页面的顶部横栏** | **开启** | 内置页面顶部横栏会随页面滚动自动收起/展开，也可用右侧按钮手动收起 | 横栏始终 56dp、没有「收起」按钮，也不自动收起 |

* **开启「通过外部浏览器连接」时会弹一次安全告警**（token 会进入剪贴板，其他应用可能读取）；
  两个开关旁各有一个 **?**，可随时查看完整说明。
* 两个开关是**全局**的：切换后所有主机都按新方式打开；编辑页里不再有每主机开关，只有一行指向设置页的提示。

### 补充：从 Termux / 已有 SSH 配置迁移（可选，进阶）

如果你平时在手机的 **Termux** 里管理 SSH（里面已经有 `~/.ssh/config` 和私钥），注意：Termux 的
`~/.ssh` 属于 Termux 这个应用，**本 App 无权直接读取**（Android 沙箱限制，与权限无关）。

**v0.2.0 推荐做法：不共用私钥，让 App 生成一把新密钥**

1. 按第 5 步在 App 内生成一把新密钥。
2. 用 **复制公钥** 得到公钥，在 Termux 里执行（或直接在远端执行）：

   ```bash
   # 在 Termux 里（已能 ssh 到远端）：
   ssh 你的远端主机 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys" <<'EOF'
   # 这里粘贴 App 复制的公钥整行
   EOF
   ```

   更简单的方式：把公钥复制到远端的 `~/.ssh/authorized_keys`（见第 5 步命令）。
3. 主机编辑页选这把新密钥即可。Termux 原来的私钥完全不用动。

**如果确实要导入 Termux 里的旧私钥**（比如服务器只授权了那一把）：

1. 在 Termux 里导出私钥到手机共享存储（先给私钥加口令更稳妥）：

   ```bash
   termux-setup-storage        # 只需第一次
   mkdir -p /sdcard/Download/dsh-ssh
   cp ~/.ssh/config /sdcard/Download/dsh-ssh/config
   # 私钥仅在确实要迁移时导出，且先加口令：ssh-keygen -p -f ~/.ssh/id_rsa
   cp ~/.ssh/id_rsa /sdcard/Download/dsh-ssh/id_rsa
   ```

2. App 里 **导入 SSH 配置 → 选择文件…** 选 `dsh-ssh/config` 导入（文件选择器类型已放宽为 `*/*`，
   没有扩展名的 config 也能选）。
3. **SSH 密钥管理… → 导入密钥对**：粘贴或从文件选择私钥，填写口令（如果有）。
4. **导入成功后立刻删除临时目录并清空剪贴板**：

   ```bash
   rm -rf /sdcard/Download/dsh-ssh
   ```

> 为什么不能直接让 App 读 `~/.ssh`、SAF 与 `ACTION_OPEN_DOCUMENT_TREE` 的细节、以及「让 Termux 代跑 ssh」
> 等替代方案，见进阶文档 [docs/android-ssh-guide.md](android-ssh-guide.md)（重点看 §4、§5）。

### 补充：SSH 密钥管理界面（生成 / 导入 / 查看 / 删除）

入口：**「更多」（⋮）→ SSH 密钥管理…**；编辑主机时点 **管理 SSH 密钥…** 也可以进入。

| 操作 | 步骤 |
|---|---|
| **生成新密钥** | 点「生成新密钥」→ 填名称（默认 `app-key-1`）→ 选 RSA 位数（2048/3072/4096，默认 3072）→ 生成。完成后会显示公钥全文，点「复制公钥」去远端 `authorized_keys` 里添加 |
| **导入密钥对** | 点「导入密钥对」→ 粘贴私钥（或「从文件导入私钥…」，≤1 MiB）→ 有口令填口令 →（可选）粘贴公钥做匹配校验 → 保存。公钥与私钥不匹配会直接拒绝 |
| **查看密钥** | 点列表中的一行：显示名称、类型、SHA256 指纹、创建时间、来源（App 生成 / 导入 / 旧版迁移）、被哪些主机使用 |
| **复制公钥** | 详情里点「复制公钥」（公钥可以公开，放心复制） |
| **查看/复制私钥** | 私钥默认隐藏；点「显示私钥」需要二次确认，「复制私钥」会提示敏感信息警告。**除非要迁移密钥，否则不建议复制私钥**；复制后请尽快清空剪贴板 |
| **重命名** | 详情里点「重命名」，只改显示名称，不动密钥本身 |
| **删除** | 详情里点「删除」。若仍有 N 台主机在用它，会明确警告：删除后这些主机将无法用私钥登录，需要重新生成/导入并到主机里重新选择 |
| **核对指纹** | 在远端执行 `ssh-keygen -lf ~/.ssh/authorized_keys`，与 App 显示的 `SHA256:…` 直接比较（格式一致：`SHA256:<标准 base64>`、无 `=` 填充），一致说明公钥装对了 |

> 生成 RSA 密钥可能需要 0.5–2 秒（3072/4096 更慢），生成期间按钮会禁用，属正常现象。

## 5. 前台服务与省电设置（建议做）

隧道要跨 App 界面存活，靠的是 Android **前台服务**（通知栏可见，系统不容易杀）。但很多手机厂商
的省电策略更激进，建议把本 App 加进白名单：

| 品牌 | 建议设置 |
|---|---|
| 原生 Android / Pixel | 设置 → 应用 → DSH 远程主机 → 电池 → 选 **无限制** |
| 小米 / Redmi | 设置 → 应用设置 → 应用管理 → DSH 远程主机 → 省电策略 → **无限制**；并在「自启动」中允许 |
| 华为 / 荣耀 | 设置 → 应用 → 应用启动管理 → DSH 远程主机 → 改为**手动管理**，允许自启动/关联启动/后台活动 |
| OPPO / 一加 / realme | 设置 → 电池 → 应用耗电管理 → DSH 远程主机 → 允许后台运行 / 不限制 |
| vivo / iQOO | 设置 → 电池 → 后台耗电管理 → DSH 远程主机 → 允许后台高耗电 |
| 三星 | 设置 → 电池 → 后台使用限制 → 把 DSH 远程主机从「睡眠应用」中移出 |

另外：在多任务界面（最近任务）把本 App 卡片「加锁 / 锁定」，也能减少被清理的概率。
**这不是必须的**，但如果你发现锁屏一会儿隧道就断，按上面设置一下。

## 7. 升级（覆盖安装）与数据保留

### 7.1 一般升级方法

* **升级方法**：拿到新版本的 APK（例如 `dsh-remote-hosts-0.2.5.apk`），像第一次一样点开安装。
  系统会提示 **「是否更新应用？」** → 点 **更新 / 安装**。
* **能保留数据的前提**：新旧 APK 用**同一个签名 keystore** 构建——本项目交付的 APK 统一由项目内
  `keystore/release.jks`（alias `dshremote`）签名。**覆盖安装必须使用同一签名**；签名一致时，
  覆盖安装会保留主机列表、凭证、SSH 密钥库和已信任的主机密钥。
* **需要先卸载的情况**（此时数据会丢）：
  * 新 APK 与已装版本的签名不同（提示「应用未安装」「签名不一致」）；
  * 新 APK 的 versionCode 比已安装的**低**（系统默认拒绝降级）。
* 升级前想备份？本 App **不支持导出凭证/私钥**（出于安全考虑），升级时请**不要卸载**，直接覆盖安装。

> 想确认当前版本：打开 App → **「更多」（⋮）→ 关于**，会显示版本号。

### 7.2 从 v0.1.0 升级到 v0.2.0（重点）

1. 直接安装 0.2.0 APK 覆盖旧版（同一 `release.jks` 签名），**数据不丢**。
2. 第一次打开 0.2.0 时会自动迁移旧数据：
   * v0.1.0 里「每台主机粘贴的私钥」会转成 **SSH 密钥库**条目（内容相同的私钥只建一条）；
   * 主机自动改为引用迁移后的密钥（`keyId`），旧的明文私钥字段被清空；
   * 迁移是幂等的，只发生一次，不会重复建条目；
   * 若某把旧私钥因格式/口令原因无法解析，该主机**保留旧内联私钥继续可用**（数据不丢），
     但不会出现在密钥库中；建议之后在编辑页重新生成/导入密钥并改选。
3. 迁移后打开 **SSH 密钥管理…** 检查：
   * 能看到自动迁移来的密钥（来源显示为「旧版迁移」），名称默认取第一个使用它的主机别名；
   * 建议把名称改成好记的（如 `pixel-dsh`），并核对指纹。
4. 打开一台旧主机 → **编辑**：**密钥**下拉框应已预选迁移后的密钥；直接保存或点「打开」验证连接。
5. 如果某台主机连接失败并提示「所选密钥已不存在，请重新选择」：进入编辑页重新选择密钥即可
   （通常出现在你手动删除过密钥之后，见 [docs/troubleshooting.md](troubleshooting.md)）。

> **UI 修复**：v0.2.0 还把顶部标题栏改成了自绘顶栏（不再用平台 ActionBar），修复了 v0.1.0 在部分
> Android 15 / 全面屏机型上「标题栏遮挡列表第一台主机」的问题；现在标题栏和列表不再重叠。

> 从更早的版本（0.1.0 之前）或修改过代码的版本升级，若安装失败提示签名不一致，只能卸载重装；
> 卸载会删除凭证和密钥（见 [§8](#8-卸载与数据清除)）。

### 7.3 从 v0.2.0 升级到 v0.2.1（小版本）

* **同一签名直接覆盖安装即可**（`release.jks` 不变），主机、凭证、SSH 密钥库、已信任主机密钥**原样保留**；
* **没有数据迁移变化**（0.2.0 已经完成过旧内联私钥迁移的，不会重复迁移）；
* 行为变化：点「打开」后、呼出浏览器前多了 **token 预校验**——token 失效/不对时 App 会直接提示
  「远端拒绝了 token（可能已失效…）」，不再打开 401 页面。更新凭证见
  [docs/troubleshooting.md §7](troubleshooting.md#7-打开异常webview-失败--401--authentication-required)
  （v0.2.5 起该预校验只在设置页开启「通过外部浏览器连接」时执行）；
* 如果升级后第一次打开遇到 token 失效提示，属于正常的旧凭证过期（远端可能重启过 `dsh web`），
  按上面的更新凭证步骤处理即可，不是升级本身的问题。

### 7.4 从 v0.2.1 升级到 v0.2.2（小版本）

* **同一签名直接覆盖安装即可**（`release.jks` 不变），主机、凭证、SSH 密钥库、已信任主机密钥**原样保留**；
* **没有数据迁移变化**；旧主机的「附加 token」默认按**开启**处理——与 0.2.1 的打开行为一致；
* 新增功能：
  * 编辑页凭证区域多一个 **「打开时在网址中附加 token」** 复选框（当时默认勾选；**v0.2.4 起新主机默认不勾选**，
    **v0.2.5 已彻底删除**，见 [§7.6](#76-从-v023-升级到-v024重要行为变化)）；
  * 隧道已打开时，**长按主机 →「复制打开网址（含 token）」** 可把完整网址复制到剪贴板，
    用于手动登录一次（v0.2.4 仍保留该入口）；
* 如果升级后发现打开方式与预期不符：v0.2.2 的每主机开关在 v0.2.4 用于选择 A/B，**v0.2.5 已删除该开关**，
  改由设置页「通过外部浏览器连接」全局决定（默认内置 WebView），见 [§7.7](#77-从-v024-升级到-v025重要行为变化)。

### 7.5 从 v0.2.2 升级到 v0.2.3（小版本，重要行为变化）

* **同一签名直接覆盖安装即可**（`release.jks` 不变），主机、凭证、SSH 密钥库、已信任主机密钥**原样保留**；
* **没有数据迁移变化**；
* 行为变化（重要）：勾选「附加 token」的主机，点「打开」后不再直接跳浏览器，而是弹出
  **「token 交接」对话框**——默认 **「复制网址并打开浏览器」**：App 复制完整 URL（含 token）并打开浏览器首页，
  **你需要到地址栏粘贴打开**。这是为了解决 Android 浏览器对「外部 App 发起 + 303 跳转」的 SameSite 拦截
  （直接打开会 401，Chrome/Firefox/Edge 都一样）。
* 「直接打开」选项（v0.2.3 当时保留）；取消勾选附加 token 的主机行为不变（当时直接打开干净网址）。
* 升级后第一次看到交接对话框是当时的新流程，按提示复制 + 地址栏粘贴即可；无需重新录入凭证。
* ⚠️ **v0.2.4 已删除该「token 交接」对话框与「直接打开」按钮**；从 0.2.3 升级到 0.2.4 请看
  [§7.6](#76-从-v023-升级到-v024重要行为变化)。

### 7.6 从 v0.2.3 升级到 v0.2.4（重要行为变化）

* **同一签名直接覆盖安装即可**（`release.jks` 不变），主机、凭证、SSH 密钥库、已信任主机密钥**原样保留**；
* **没有数据迁移变化**（数据与凭证格式不变）；
* 行为变化（重要）：打开方式改为两种，由编辑页 **「打开时在网址中附加 token」** 开关决定
  （**该开关已在 v0.2.5 删除**，现由设置页全局开关决定，见 [§7.7](#77-从-v024-升级到-v025重要行为变化)）：
  * **不勾选（模式 B，App 内置 WebView 全自动打开）**：App 经隧道完成 token 交换、把登录 cookie 注入
    内置系统 WebView，再加载**不含 token** 的 `http://127.0.0.1:<端口>/`。**不打开外部浏览器、不需要粘贴**。
    v0.2.4 起**新添加的主机默认使用这种模式**。
  * **勾选（模式 A，复制网址 + 浏览器粘贴）**：点「打开」后**没有任何对话框**——App 把完整含 token 网址复制到
    敏感剪贴板、打开**默认浏览器首页**，你在浏览器**地址栏粘贴**打开。v0.2.3 的「token 交接」对话框和
    「直接打开」按钮**已删除**；App 也不再直接把隧道网址交给浏览器（「直接网址」模式除外）。
* **已有主机保留原来的开关值**：升级前勾选的 = 模式 A（复制+粘贴），升级前未勾选的 = 模式 B（App 内自动打开）。
  升级不会改变已有主机的行为；v0.2.5 起该开关被删除，已有主机的开关值不再生效（见 [§7.7](#77-从-v024-升级到-v025重要行为变化)）。
* 升级后第一次点「打开」：
  * 模式 B → App 直接在内置 WebView 里打开远端 DSH UI（失败会显示错误面板：去编辑凭证 / 重试 / 关闭）；
  * 模式 A → 浏览器首页被打开 + Toast「网址已复制，请在浏览器地址栏粘贴打开」，粘贴即可。
* 「附加 token」开关旁新增 **?** 帮助按钮；从「不勾选」切到「勾选」时会弹一次说明/安全告警。
* 日常推荐使用**模式 B**（无需粘贴、WebView 加载的地址不含 token）；需要外部浏览器时再用模式 A。
* 详细排障见 [docs/troubleshooting.md §7](troubleshooting.md#7-打开异常webview-失败--401--authentication-required)。

### 7.7 从 v0.2.4 升级到 v0.2.5（重要行为变化）

* **同一签名直接覆盖安装即可**（`release.jks` 不变，alias `dshremote`），已实测 **0.2.4 → 0.2.5 设备数据保留**：
  主机列表、凭证、SSH 密钥库、已信任的主机密钥**原样保留**；
* **没有数据迁移变化，也不需要手动迁移**：每主机的 `appendToken` 字段已从模型/JSON/编辑页删除，
  旧版加密存储里多余的该字段在解码时被**忽略**，主机正常加载；
* 行为变化（重要）：**打开方式改为全局设置**
  * 主页 **「更多」（⋮）→「设置」** 新增两个开关：**「通过外部浏览器连接」**（默认**关闭** = 内置 WebView 全自动打开）
    与 **「自动收起内置页面的顶部横栏」**（默认开启）；
  * **旧主机的每主机开关值被丢弃**，不再生效；升级后统一按全局默认走 **内置 WebView**；
  * 编辑页原来的每主机开关与 **?** 帮助已移除，改为一行提示：「打开方式（外部浏览器 / 内置页面）已改为全局设置：
    请在主页「更多 → 设置」中切换。」
  * 设置页的开关**立即生效并持久化**（SharedPreferences 文件 `settings`，只存布尔值，不存任何凭证）。
    开启「通过外部浏览器连接」时会弹一次安全告警，开关旁 **?** 可查看完整说明；
  * 内置页面新增顶部横栏收起：展开 56dp / 收起 32dp，向下滚动自动收起、滚回顶部自动展开，
    右侧按钮可手动收起，详见 [§4 第 8 步](#第-8-步看到远端-dsh-ui)；
* 想恢复成「内置页面」：到设置页**关闭**「通过外部浏览器连接」即可（默认就是关闭）；
* 详细排障见 [docs/troubleshooting.md §16](troubleshooting.md#16-设置页与打开方式v025)。

## 8. 卸载与数据清除

**卸载方法**（任选其一）：

* 长按桌面图标 → **应用信息** → **卸载**；
* 设置 → 应用 → 应用管理 → **DSH 远程主机** → **卸载**。

**卸载会发生什么：**

1. 所有隧道立即关闭，前台服务停止。
2. App 的私有数据（`hosts.enc` 加密文件：主机列表、**SSH 密钥库**、已信任的主机密钥）**全部删除**。
3. Android Keystore 里用于加密的密钥一并失效——即使你之前用某种方式拿到了 `hosts.enc` 文件，
   卸载后也无法再解密。
4. 重新安装后是全新的空列表/空密钥库，需要重新导入配置、重新生成或导入密钥、重新确认主机密钥。

> **只有卸载、没有备份**：这是有意设计（私钥与凭证不应该能随随便便导出）。如果你只是换手机，
> 请在远端 `~/.ssh/authorized_keys` 里删掉旧手机的公钥，再为新手机生成一把新密钥。
> 备份提醒：如果你曾经把某把私钥导出到别处，请自行保管好；App 内的密钥会随卸载一起销毁。

## 9. 真机首次验收清单（可选，但建议做一遍）

本项目开发环境没有 Android 真机/模拟器，下列清单来自行为契约（[docs/app-spec.md](app-spec.md#10-验收清单)），
建议你在自己的手机上按顺序验证一次：

> v0.2.5 的**自动化验收已完成**：`tools/check-apk.ps1` **76/76 PASS**、JVM 离线单测 **415 checks** 全 PASS、
> 真实 SSH（`-RequireSsh`）PASS 且无 SKIP。下列是仍需**真机人工确认**的 UI/交互项（尤其新的横栏收起）。

**基础流程**

- [ ] 能正常安装并启动 App，空列表显示「还没有主机」。
- [ ] 导入一份真实的 SSH config，预览的主机数量和 `~/.ssh/config` 里的一致。
- [ ] 编辑一台主机，粘贴凭证 URL 后能保存并显示「已配置」。
- [ ] **编辑页不再有每主机开关**：只显示一行「打开方式（外部浏览器 / 内置页面）已改为全局设置…」提示，
      没有「打开时在网址中附加 token」复选框。
- [ ] **设置页（v0.2.5）**：主页「更多」（⋮）→ **设置** 能打开；两个开关都存在且默认值为
      **「通过外部浏览器连接」= 关闭**、**「自动收起内置页面的顶部横栏」= 开启**；切换后退出再进入仍保持；
      两个 **?** 帮助按钮都能弹出说明；开启「通过外部浏览器连接」时弹一次安全告警。
- [ ] 点「打开」→ 首次出现主机密钥确认（指纹与远端 `ssh-keygen -lf` 输出一致）→ 信任后建立隧道。

      **不打开外部浏览器**，App 内置 WebView 自动显示远端 DSH UI（可操作、WebSocket 实时更新正常）；
      WebView 里加载的地址应为不含 token 的 `http://127.0.0.1:<端口>/`。
- [ ] **内置页面横栏收起（v0.2.5）**：在页面里向下滚动 → 顶部横栏自动收起为一行 32dp 的主机名；
      滚回页面顶部 → 自动展开为 56dp（返回箭头 + 标题 + 副标题 + 收起按钮）；向上滚动（非顶部）不会自动展开；
      点按收起后的横栏能展开；右侧「收起」按钮能随时手动收起；收起后**不遮挡 WebView 内容**。
- [ ] **横栏设置门控（v0.2.5）**：到设置页关闭「自动收起内置页面的顶部横栏」→ 重新「打开」→
      横栏始终 56dp、无「收起」按钮、滚动也不自动收起；重新开启后恢复。
- [ ] **错误面板与横栏（v0.2.5）**：让 token 失效触发错误面板 → 横栏应自动展开为 56dp。
- [ ] **外部浏览器模式（v0.2.5）**：设置页开启「通过外部浏览器连接」（弹一次告警）→ 点「打开」→
      **没有任何对话框**；剪贴板里是完整 `http://127.0.0.1:<端口>/?token=…`（**原封不动**），
      默认浏览器**首页**被打开，并出现 Toast「网址已复制，请在浏览器地址栏粘贴打开」→ 在地址栏粘贴 →
      远端 DSH UI 正常显示。完成后到设置页关闭该开关，确认恢复内置页面。
- [ ] **失败面板（内置页面）**：用一个**故意改错**的 token 点「打开」→ WebView 显示错误面板
      「远端拒绝了 token…」，提供 **去编辑凭证 / 重试 / 关闭** 三个按钮；把凭证改回正确 URL 后能正常打开。
- [ ] **token 预校验（仅外部浏览器模式）**：开启「通过外部浏览器连接」后用错 token 点「打开」，App 直接提示
