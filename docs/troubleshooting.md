# 故障排查（按症状查）

先记住三个「万能第一步」：

1. **重新点一次「打开」**——本 App 不做自动重连，很多时候隧道只是断了。
2. **「更多」（⋮）→ 全部断开**，然后重新打开——清掉半死状态的隧道。
3. **确认手机网络能到 SSH 主机**（同一 Wi-Fi / 校园网 / VPN），并确认远端 `dsh web` 还在跑。

> v0.2.0 起主机认证改为「从密钥库选择密钥」。如果提示认证失败 / 缺少凭证，先确认该主机选的密钥
> 还在（没被删除）、私钥口令填对、公钥已装到远端——见 [§15](#15-ssh-密钥管理相关问题v020)。
>
> **v0.2.5 起打开方式由「更多 → 设置」的全局开关决定**（每主机开关已删除）：
> * **「通过外部浏览器连接」关闭（默认）= 内置 WebView**：点「打开」后 App 用**内置 WebView 全自动打开**
>   远端 DSH UI，不经过外部浏览器；失败时 App 内显示错误面板（**去编辑凭证 / 重试 / 关闭**）。
> * **「通过外部浏览器连接」开启 = 外部浏览器模式**：点「打开」后 App 把含 token 的完整网址复制到敏感剪贴板、
>   打开**浏览器首页**，你在浏览器**地址栏粘贴**打开（**没有任何对话框**）。
> * 每主机的「打开时在网址中附加 token」开关与 `appendToken` 字段已在 v0.2.5 **删除**；旧主机的选择不再生效。
>   设置相关 FAQ（开关去哪了、怎么切换、横栏不自动收起、剪贴板提示、升级变化）见 [§16](#16-设置页与打开方式v025)。
>
> v0.2.3 的「token 交接」对话框与「直接打开」按钮已删除；App 也不会再把隧道网址直接交给浏览器
> （「直接网址」模式除外）。打开异常 / 401 / `authentication required` 的统一入口见
> [§7](#7-打开异常webview-失败--401--authentication-required)。

App 的错误提示分几类（对应行为契约 [docs/app-spec.md §9](app-spec.md#9-错误分类与中文提示ui-映射)）：

| 提示关键词 | 含义 | 跳到本文 |
|---|---|---|
| 配置不完整或格式错误 | `bad-request`：字段/凭证 URL 格式问题 | [§3](#3-保存或打开时提示配置不完整--格式错误) |
| SSH 认证失败或缺少凭证 | `needs-credentials` | [§4](#4-提示ssh-认证失败或缺少凭证) |

| 连不上远端：网络、端口、跳板机 | `unreachable` | [§5](#5-提示连不上远端) |
| 主机密钥已变更 | `host-key-changed` | [§6](#6-提示主机密钥已变更) |
| 内部错误 | `internal`（message 已脱敏） | [§11](#11-提示内部错误) |

## 1. 安装失败

| 现象 | 原因 | 解决 |
|---|---|---|
| 提示「禁止安装未知应用」「为安全起见…」 | 没有给打开 APK 的 App 授权 | 按 [docs/install.md §2](install.md#2-允许安装未知应用) 授权：设置 → 应用 → 特殊应用权限 → 安装未知应用 → 选中来源 App → 允许。各品牌路径见 install.md 的表格 |

| 提示「应用未安装」「与已安装的应用签名不一致」 | 手机上已有一个**不同签名**的同包名 App（比如别人构建的版本） | 先卸载旧版（**数据会丢**，凭证需要重填），再安装新 APK；或者用同一签名 keystore 重新构建（见 [docs/build.md](build.md)） |
| 提示「应用未安装」，没有更多信息 | 安装包与系统不兼容、存储空间不足、或降级安装 | 确认 Android 版本 ≥ 8.0；清理存储；不要安装 versionCode 更低的版本（需先卸载） |
| 设置了「允许未知来源」但仍无法安装 | 公司/学校统一管理的设备（MDM）禁止侧载 | 无法绕过，换一台自己控制的手机，或联系设备管理员 |
| 手机安装时被「Play 保护机制」拦截 | Google 对侧载 APK 的扫描提示 | 确认 APK 来源可信后选择「仍要安装」；不确定就不要装 |
| 找不到「安装未知应用」入口 | 各品牌设置改版 | 在「设置」顶部搜索框搜 **未知应用** 或 **安装未知应用** |

## 2. 打开 App 后没有主机 / 导入后列表为空

| 现象 | 排查 |
|---|---|
| 列表显示「还没有主机」 | 正常：先 **「更多」（⋮）→ 导入 SSH 配置** 或 **「更多」（⋮）→ 添加主机** |
| 导入时提示「没有识别到任何具体主机（通配 Host 不会被导入）」 | 你的 config 里只有 `Host *` 这类通配块，没有具体主机名。手动「添加主机」，或在 config 里加一个具体 `Host 名字` 块 |
| 识别到的主机比 config 里少 | 含 `Include` 的文件不会被展开（会给出警告）。把 `Include` 指向的文件内容合并到同一份 config 里再导入 |
| 粘贴后解析失败 | 检查粘贴的是纯文本 config（不是 Word/PDF）；每行是 `关键字 值` 格式；`#` 开头是注释。可先把内容粘贴到记事本确认没有富文本 |
| 「选择文件…」里找不到 config 文件 | 用文件选择器左侧/顶部的「下载」或「最近」分类找；确认文件已传到手机存储；文件名没有扩展名也可以选 |

> `IdentityFile ...` 的警告是正常现象：手机读不到电脑上的私钥文件。v0.2.0 起请到
> **「更多」（⋮）→ SSH 密钥管理…** 生成/导入密钥，再到主机编辑页选择；不需要逐台粘贴私钥内容。

## 3. 保存或打开时提示「配置不完整 / 格式错误」

按 App 的提示补字段。常见原因：

* **别名为空**，或别名与已有主机重复（别名是唯一键）。
* **SSH 用户名**没填。
* 认证方式选了「私钥」，但**没有选择密钥**（或原来选的密钥已被删除）——到密钥管理里生成/导入一把，
  再回到编辑页的「密钥」下拉框选择。
* **DSH 凭证粘贴错**：必须是 `http(s)://...?token=...` 形式的完整 URL，且带 `token=` 参数；
  常见错误是只复制了 `http://127.0.0.1:<端口>/` 而漏了 `?token=...`，或把整行日志里的引号/空格也带进来了。
* **访问方式选「直接网址」**：URL 必须是 `http://` 或 `https://` 开头且包含主机名。

在编辑页粘贴凭证 URL 后，输入框下方会实时解析并显示端口；显示红色错误就按提示改。

## 4. 提示「SSH 认证失败或缺少凭证」

这是 SSH 登录没成功。逐项检查：

1. **用户名 / 端口**：`user@host:port` 里的用户名和端口是否和电脑上 `ssh` 时一致
   （很多机器的 SSH 不是 22 端口）。
2. **密码认证**：
   * 确认密码正确；注意大小写和输入法。
   * 有些服务器**禁用了密码登录**（`PasswordAuthentication no`），只能改用私钥。
   * 有些服务器用双因素/键盘交互认证（keyboard-interactive），App 对这类服务器的支持有限。
3. **私钥认证（v0.2.0：密钥库 + 密钥选择）**：
   * 先确认编辑页「**密钥**」下拉框确实选中了一把密钥（不是空白）；列表为空时点 **管理 SSH 密钥…** 去生成/导入。
   * **公钥是否已加到远端** `~/.ssh/authorized_keys`：在密钥详情里复制公钥，整行追加到
     `~/.ssh/authorized_keys`（服务器端一般要求 `~/.ssh` 700、`authorized_keys` 600）。
     可以用 `ssh-keygen -lf ~/.ssh/authorized_keys` 核对指纹，与 App 里显示的 `SHA256:…` 直接比较
     （两边格式一致：`SHA256:<标准 base64>`、无 `=` 填充）。
   * **口令**：导入的密钥如果带口令，连接时会用到导入时保存的口令；若导入时口令填错，导入会被拒绝，
     请到密钥管理里删除后重新导入。
   * **兼容性**：App 生成的 RSA 密钥兼容性最好；**ed25519 私钥能否使用取决于手机系统提供的加密实现**，
     个别老系统不支持。遇到无法连接/解析失败，建议改用 App 生成的 RSA 密钥。
   * **“所选密钥已不存在，请重新选择”**：说明该主机引用的密钥被删除了。到密钥管理里重新生成/导入，
     再回编辑页重新选择即可（见 [§15](#15-ssh-密钥管理相关问题v020)）。
4. **跳板机场景**：当前版本（0.2.x）**用目标主机的认证材料（密码或所选密钥）去登录跳板机**（见
   [docs/architecture.md §4](architecture.md#4-认证与密钥)）。如果跳板机和目标主机需要**不同的用户名/密码/私钥**，
   当前版本做不到，请先改用「跳板机 + 目标机同一套凭证」的方式，或使用其他网络入口。
5. 改完 → **保存** → 回到列表重新点「打开」。

## 5. 提示「连不上远端」

先分清是「网络到不了」还是「认证/密钥问题」：如果错误是 `needs-credentials`，看 §4；这里是
`unreachable`。

1. **手机网络能不能到目标？**
   * 手机浏览器访问 `http://<主机>:<SSH端口>` 不一定有意义（SSH 不是 HTTP），但可以确认网络是否连通：
     用手机的终端类 App 或电脑 `ping`/`nc` 测试；最简单是**手机连上同一 Wi-Fi / 校园网 / VPN**。
   * 远端主机如果只在校园网/公司内网可见，手机用 4G 是连不上的，需要连对应 Wi-Fi 或 VPN。
2. **端口对吗？** SSH 端口不一定是 22（例如自定义成 20000）；和电脑上 `ssh -p` 用的端口保持一致。
3. **主机名/IP 对吗？** 手机不认你电脑上的 `~/.ssh/config` 里的 `HostName` 别名，App 会使用导入时的
   `HostName`；如果 config 里只写了别名、HostName 没写，编辑页里补上真实的 IP/域名。
4. **服务器防火墙/安全组**是否允许你的手机所在网络访问 SSH 端口。
5. **跳板机（ProxyJump）失败**：
   * 跳板机本身能否连通（先单独配置一台「跳板机主机」测试，或电脑上先验证 `ssh -J`）；
   * 跳板机地址写成 `user@host:port`，或直接填**主机列表里的别名**；
   * 跳板机认证材料规则见 §4 第 4 条；
   * 目标主机地址是在**跳板机视角**能访问的地址（例如内网 `192.0.2.10`），不是你手机的视角；
   * 首次连接会**分别确认两次指纹**（先跳板机、后目标主机），两个都要核对；
   * **只支持单级跳板**：写成逗号分隔的多级（`jump1,jump2`）会被明确拒绝，请改用单级或换网络入口。
6. **端口探测失败/本地端口被占用**：App 会在 20000–60000 里自动找空闲端口，一般不需要你操心；
   如果反复失败，点「全部断开」后重试，或重启手机。
7. **连接超时（25 秒）**：通常是网络慢/不通。检查网络后重试；仍失败看 §8。

## 6. 提示「主机密钥已变更」

App 保存过这台主机的 SSH 公钥，这次连接拿到的不一样。**不要急着继续**：

1. **先确认是不是管理员真的换了机器/重装了系统**（换机器、重装 sshd、集群节点重建都会导致密钥变化）。
2. 在远端机器上核对当前指纹：

   ```bash
   ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
   ssh-keygen -lf /etc/ssh/ssh_host_rsa_key.pub
   ```

3. 如果确认换了密钥：编辑主机 → **重置此主机的密钥信任** 后重新打开，重新确认新指纹。
4. 如果**没有**换过机器：可能是中间人攻击或连到了错误地址，**停止连接**，检查网络/跳板机是否被劫持。

## 7. 打开异常（WebView 失败 / 401 / authentication required）

v0.2.5 起有两种打开方式，由**设置页**的全局开关 **「通过外部浏览器连接」** 决定
（每主机的开关已删除，见 [§16](#16-设置页与打开方式v025)）。先对号入座，再按对应小节排查。

### 7.1 两种打开方式（v0.2.5：全局设置）

| | **内置 WebView（默认）：全局开关关闭** | **外部浏览器模式：全局开关开启** |
|---|---|---|
| 点「打开」后 | App 在**内置 WebView** 里自动打开远端 DSH UI | App 把完整含 token 网址复制到敏感剪贴板 + 打开**浏览器首页**（无对话框） |
| 是否用外部浏览器 | **否** | **是**（只打开浏览器首页，网址由你粘贴） |
| 失败时看到 | App 内 WebView 错误面板：**去编辑凭证 / 重试 / 关闭** | App 错误对话框（如「远端拒绝了 token…」），不会复制网址/开浏览器 |
| 排查重点 | token 交换 / cookie 注入 / WebView / 隧道 / 横栏收起 | 粘贴是否完整、端口是否本次隧道、浏览器 401 |
| 详见 | [§7.2](#72-模式-bwebview失败面板与排查) | [§7.3](#73-模式-a复制--浏览器粘贴流程与排查) |

* 全局默认是**内置 WebView**（设置页「通过外部浏览器连接」关闭）；从 v0.2.4 升级的旧主机不再保留每主机选择。
* 切换：主页 **「更多」（⋮）→「设置」** → 打开/关闭「通过外部浏览器连接」→ 回列表重新「打开」。
  开启时会弹一次说明/安全告警；开关旁的 **?** 可随时查看说明。
* 「直接网址」模式（DIRECT_URL，你自己填了反代/穿透地址）仍用系统浏览器直接打开该外部网址，不属于本文范围。

> ⚠️ v0.2.4 已删除「App 直接把隧道网址交给浏览器」和 v0.2.3 的「token 交接」对话框；
> v0.2.5 又删除了每主机的「附加 token」开关。你**不会**再看到「直接打开」按钮或「复制网址并打开浏览器」弹窗。

### 7.2 模式 B（WebView）失败面板与排查

> 本节标题沿用 v0.2.4 的“模式 B”；v0.2.5 起这就是**默认的内置 WebView**（设置页「通过外部浏览器连接」关闭）。

**正常表现**：点「打开」→ 行内「连接中…」→ 隧道就绪后 App 自动进入 WebView 页面 → 很短的进度条 →
远端 DSH UI 出现，可直接操作；WebSocket 实时更新也在 App 内生效。

**失败表现**：WebView 内容区显示 **「无法打开 DSH 页面」** 错误面板，常见提示与处理：

| 面板提示 | 含义 | 处理 |
|---|---|---|
| 远端拒绝了 token（可能已失效：dsh web 重启会换 token）… | 401/403：token 不对或已过期 | 点 **去编辑凭证** → 粘贴远端**最新** `dsh web` 打印的 URL → 保存 → 回列表重新「打开」；详见 [§7.4](#74-token-失效与更新凭证) |
| 无法通过隧道读取远端 dsh web 响应 | 经隧道请求超时/连接失败（隧道刚断、远端 `dsh web` 没跑/端口不对） | 点 **重试**；反复失败先「全部断开」再「打开」，并检查 [§5](#5-提示连不上远端) 与远端 `dsh web` 是否在监听 |
| 远端未返回登录 cookie | 响应里没有 `dsh-auth-*` 的 `Set-Cookie`（不是标准 `dsh web`，或中间代理改写了响应） | 确认远端是标准 `dsh web`；若有反向代理，检查是否保留 `Set-Cookie`；仍不行可临时开启外部浏览器模式（[§7.3](#73-模式-a复制--浏览器粘贴流程与排查)）对比测试 |
| 远端返回了 HTTP N，无法自动登录 | token 交换请求返回其他 4xx/5xx（远端异常或中间网关拦截） | 先点 **重试**；确认远端 `dsh web` 正常、没有反向代理/网关改写响应；仍失败可点 **去编辑凭证** 检查凭证，或用外部浏览器模式（[§7.3](#73-模式-a复制--浏览器粘贴流程与排查)）对比测试 |
| 页面加载失败：… | 拿到 cookie 后 WebView 加载 `127.0.0.1:<端口>/` 时主框架错误（常见于隧道在交换后断开） | 点 **重试**（App 会重新交换 token 并加载）；隧道若已断，回列表重新「打开」 |
| 主机不存在 / 隧道端口无效 / 没有保存 token | 主机被删除、打开时隧道端口异常，或内置 WebView 模式下凭证里没有 token 可用 | 回主机列表重新「打开」；仍失败就编辑主机重新粘贴凭证 |

> **「去编辑凭证」** 会打开该主机的编辑页并回到主机列表（当前 WebView 关闭，隧道保持）；
> 保存新凭证后**重新点「打开」**即可。**「关闭」** 只关掉 WebView 页面，隧道与后台服务保持。
> 面板只有「关闭」按钮的情况（主机不存在/端口无效）需要先回列表重新「打开」或修复主机配置。

其他内置 WebView 现象：

| 现象 | 排查 |
|---|---|
| 没出现错误面板，但一直白屏/转圈 | ①隧道是否还在（通知栏常驻通知是否消失；状态 chip 是否「已连接」）→「全部断开」后重新打开；②远端 `dsh web` 是否在跑；③手机系统的 **Android System WebView** 是否被停用/太旧（设置 → 应用 → 显示系统应用 → Android System WebView → 启用/更新；或更新 Chrome） |
| WebView 里仍显示 `authentication required` | 先点 **重试**（App 会重新交换 token、重新注入 cookie）；仍失败按 [§7.4](#74-token-失效与更新凭证) 更新凭证 |
| 页面能打开但实时更新不动 | WebSocket 依赖隧道与前台服务：确认 App 没被省电策略杀（[install.md §5](install.md#5-前台服务与省电设置建议做)）、隧道没断；切回前台稍等或重新「打开」 |
| 点击页面里的外部链接 | 其他 http/https 链接交给**系统浏览器**打开（不在 App 内继续）；其他 scheme（如 `mailto:`）交给系统处理，无应用处理时提示失败 |
| 返回键 | 先返回 WebView 里的上一页；没有上一页时退出 WebView 回到主机列表（隧道保持，可再次「打开」） |
| 系统浏览器里登录过，App 内却要重新登录 | 正常：WebView 的 cookie 与系统浏览器是**两套**。内置 WebView 每次「打开」会自动完成登录，无需操作 |
| 想看/切换打开方式 | 主页「更多」→「设置」→「通过外部浏览器连接」；或在列表长按主机 →「复制打开网址（含 token）」（隧道 OPEN 时可用） |

> 内置 WebView **不会**打开外部浏览器。如果点「打开」后跳到了浏览器，说明设置页开启了「通过外部浏览器连接」，
> 或「访问方式」是「直接网址」。

### 7.3 模式 A：复制 + 浏览器粘贴流程与排查

> 本节标题沿用 v0.2.4 的“模式 A”；v0.2.5 起该路径由**设置页**的「通过外部浏览器连接」开启（每主机开关已删除）。

**正常表现（4 步）**：

1. 设置页**开启**「通过外部浏览器连接」（开启时会弹一次告警）。
2. 点「打开」→ 隧道建立 → App **无对话框**：
   * 把完整网址 `http://127.0.0.1:<隧道端口>/?token=<token>`（**原封不动**）复制到**敏感剪贴板**；
   * 打开**默认浏览器首页**（不是目标网址）；
   * Toast：「网址已复制，请在浏览器地址栏粘贴打开」。
3. 到浏览器**地址栏长按 → 粘贴 → 打开**（这一步必须做）。
4. 浏览器先带 token 请求一次、再 303 跳到干净地址 → 远端 DSH UI 正常显示。

**常见问题**：

| 现象 | 原因与处理 |
|---|---|
| 浏览器没被打开 | 极少数设备没有可响应的默认浏览器。App 只会 Toast 提示（**不再回退为直接打开网址**）；手动打开任意浏览器 → 地址栏粘贴剪贴板里的网址即可 |
| 剪贴板里没有网址 / 已被其他内容覆盖 | 隧道已打开时**长按主机 →「复制打开网址（含 token）」**重新复制；未打开时先点「打开」 |
| 浏览器显示 401 / `authentication required` | ① 是否**粘贴网址打开**（不要点旧书签/旧标签；v0.2.4 已无直接跳转）；② 端口是否**本次隧道**的（隧道重开后端口会变）；③ 是否粘全（含 `?token=…`）；④ token 是否失效（App 预校验会提示，按 [§7.4](#74-token-失效与更新凭证) 更新）。原理见 [§7.5](#75-samesite-根因与-v024-的两种方式) |
| 粘贴后打不开 / 连接被拒 | 隧道可能已断：看通知栏常驻通知与主机状态 chip；旧剪贴板网址可能是**上一次隧道**的端口，重新点「打开」→ 重新复制粘贴 |
| App 提示「远端拒绝了 token（可能已失效…）」 | 外部浏览器模式的隧道内**预校验**失败（401/403）：token 确实失效/不对，**不会**复制网址、不会开浏览器。按 [§7.4](#74-token-失效与更新凭证) 更新凭证 |
| 告警/说明在哪里 | 设置页**开启**该开关时自动弹一次；平时点开关旁的 **?** 查看（含 SameSite 限制与剪贴板安全提示） |
| 想改回内置页面 | 设置页**关闭**「通过外部浏览器连接」→ 回列表重新「打开」 |

> 外部浏览器模式的 cookie 在**你的浏览器**里；隧道关闭/重开后本地端口可能变化，旧 cookie 不再适用 →
> 重新点「打开」→ 复制 → 粘贴即可。

### 7.4 token 失效与更新凭证

**判据**：
* 外部浏览器模式：点「打开」后 App 直接提示「**远端拒绝了 token（可能已失效：dsh web 重启会换 token）…**」；
* 内置 WebView：WebView 错误面板显示「**远端拒绝了 token（可能已失效…）**」。

最常见原因：**远端 `dsh web` 重启后换了新 token**，或凭证 URL 复制错/端口错。

1. 到**远端机器**确认/重新启动 `dsh web`，从**最新输出**复制完整
   `http://127.0.0.1:<端口>/?token=<令牌>`（`dsh web` 跑在 tmux/screen/nohup 里时先找到它再重启，
   例如 `ps aux | grep dsh`）。
2. 打开 App 的编辑页：
   * 内置 WebView：在 WebView 错误面板点 **去编辑凭证**；
   * 外部浏览器模式 / 任意：主机列表 → 该主机 **编辑**。
3. 把**新 URL** 粘贴到「DSH 凭证」→ **保存**。
   * ⚠️ 编辑已有主机时，凭证框**留空 = 保留旧 token**；必须粘贴新 URL 覆盖，否则还是旧的。
   * 保存后输入框下方会显示解析出的端口和掩码 token（`abc…xyz`），可用来确认换了新值。
4. 回列表重新点 **打开**：
   * 内置 WebView：App 自动用新 token 交换 cookie 并加载；
   * 外部浏览器模式：App 复制新网址 + 打开浏览器首页，重新粘贴登录一次。
5. 浏览器/WebView 若还停在旧页面：关掉旧标签或重新「打开」。

### 7.5 SameSite 根因与 v0.2.4 的两种方式

> 本节标题保留 v0.2.4 的历史命名；v0.2.5 起两条路径仍保留，但由设置页的全局开关选择（见 [§16](#16-设置页与打开方式v025)）。

* 远端 `dsh web` 的登录握手是：`GET /?token=…` → **303 + `Set-Cookie: dsh-auth-…; SameSite=Strict`**
  → 跳转 `./`；只有带上这个 cookie 的请求才返回 UI，否则 401 + `authentication required`。
* App 的 token 预校验在隧道内由 App 自己发起，能收到 303 说明 **token 本身有效**；问题出在**浏览器侧**：
  Android 浏览器把「由另一个 App 发起、并且经过 303 重定向」的导航判定为 **cross-site**，拒绝在后续请求里
  携带 `SameSite=Strict` 的登录 cookie → 浏览器显示 401。**Chrome 109+ / Firefox 109+ / Edge 109+ 都受影响，
  换浏览器没有用**，也不是 App 没把 token 放进网址。
* v0.2.4 引入、v0.2.5 保留的对策：
  * **内置 WebView（默认）**：不用外部浏览器。App 经隧道请求 `/?token=…` 拿到 `Set-Cookie`，把 `dsh-auth-*`
    注入 **App 自己的 WebView**（CookieManager），再加载**不含 token** 的 `http://127.0.0.1:<端口>/`。
    登录握手全在 App 进程内完成，没有跨 App 导航 → 不受 SameSite 拦截。
  * **外部浏览器模式**：仍用外部浏览器，但改由**你在地址栏粘贴**。手动粘贴属于**用户自己发起的导航**，
    浏览器按同站处理，会正常完成登录握手。App 只复制 URL 文本，**从不向外部浏览器传递 cookie**。
* v0.2.4 **删除**了「App 用 `ACTION_VIEW` 直接打开隧道网址」的路径（「直接网址」模式除外），
  也删除了 v0.2.3 的交接对话框；v0.2.5 把两条路径的选择升级为全局设置，二者都是正式支持路径。

### 7.6 桌面端对照验证（判断 token 是否真的有效）

在电脑上（能 SSH 到那台主机）用同一条隧道验证远端 token：

```bash
# 电脑上执行：把 18080 换成任意本机空闲端口，<远端 dsh web 端口> 换成凭证 URL 里的端口
ssh -N -L 18080:127.0.0.1:<远端 dsh web 端口> <user>@<host>
```

然后电脑浏览器打开：

```text
http://127.0.0.1:18080/?token=<令牌>
```

* 页面自动跳转并显示 DSH UI → token 有效：手机端用内置 WebView（默认）或外部浏览器模式（复制 + 粘贴）；
* 显示 `authentication required` / 401 → token 已失效或复制错，回 §7.4 换新 token；
* 连接被拒 → 隧道或远端服务本身有问题，见 §5/§8。

也可以用 curl 只看状态码（不会打开页面）：

```bash
curl -i "http://127.0.0.1:18080/?token=<令牌>"
# 正常：HTTP/1.1 303 + Set-Cookie: dsh-auth-…
# token 失效：HTTP/1.1 401
```

> 验证完记得 `Ctrl+C` 结束 `ssh -L`。**不要把带 token 的 URL 发到群里/截图**。

### 7.7 其他可能

* 打开的是**旧的地址/标签页**（隧道端口已经变了）：关掉旧标签，重新从 App 点「打开」复制粘贴。
* 远端 `dsh web` 没在跑或换了端口：让远端管理员确认 `dsh web` 正在监听，并拿到新的端口和 token。
* 远端服务刚重启完还没就绪：等几秒重试（App 的就绪探测/预校验/WebView token 交换也会提示）。
* 换了手机浏览器（Edge/Chrome/Firefox）仍然 401：这是 §7.5 的浏览器策略限制，**不用再换浏览器**；
  外部浏览器模式用「地址栏粘贴」流程，日常直接用默认的内置 WebView 即可。
* 手机系统 WebView 有多个实现（Chrome / Android System WebView / 厂商浏览器内核）：如果内置 WebView 一直失败，
  在系统设置里切换/更新默认 WebView 实现后再试。

## 8. 隧道断 / 一直「连接中…」/ 通知消失

|---|---|
| 锁屏一会儿后页面打不开（App 内 WebView 或浏览器） | 手机省电策略杀掉了前台服务。按 [docs/install.md §5](install.md#5-前台服务与省电设置建议做) 设置「无限制电量/自启动」，并在最近任务里给 App 加锁 |

| 电脑上 `ssh -L` 能连、App 连不上 | 对比两者的端口、用户名、认证方式、密钥选择、跳板机配置；注意 App 的主机密钥信任表是独立的，第一次连接需要确认指纹 |

## 9. 通知不显示 / 没有「全部断开」按钮

1. **Android 13+ 通知权限**：设置 → 应用 → 通知 → 找到「DSH 远程主机」→ 允许通知。
   （有的品牌在：设置 → 通知和状态栏 → 应用通知管理 → DSH 远程主机。）
2. **通知渠道被关闭**：App 使用名为「SSH 隧道」的通知渠道。在应用通知设置里展开渠道，
   确认「SSH 隧道」没有被关闭或静音。
3. **免打扰模式**：系统免打扰可能隐藏通知，检查是否开启。
4. 即使没有通知，隧道本身仍能工作（前台服务被允许在无通知权限时运行）；关闭隧道用 App 菜单里的
   **「更多」（⋮）→ 全部断开**。

## 10. App 被系统杀掉 / 后台被杀

Android 厂商 ROM 的省电策略可能随时清理后台。表现：切回 App 后隧道状态不对、页面（WebView/浏览器）加载失败。

* 按 [docs/install.md §5](install.md#5-前台服务与省电设置建议做) 加入省电白名单、允许自启动；
* 在最近任务界面把 App 卡片「加锁」；
* 不要把 App 从最近任务里划掉——划掉通常会停止前台服务；
* 重新打开 App 后点「打开」会重新建隧道。

> 这是 Android 平台限制，不是 App 的 bug；桌面端不存在这个问题。

## 13. 一分钟自检清单

- [ ] 手机 Android 8.0+，App 已安装并能启动。

- [ ] 主机编辑页：主机名、用户、端口完整且正确。

## 14. 主机列表突然变空 / 感觉数据丢了

先别慌，按原因排查：

| 可能原因 | 说明与处理 |
|---|---|
| 卸载过 App / 在系统设置里「清除数据」 | 这是设计行为：**卸载或清除数据会删除全部凭证与密钥库**（加密密钥也随之失效），只能重新导入/填写 |
| 换手机 / 系统恢复后重装 | App 设置了 `allowBackup=false`，**凭证与密钥不参与系统备份**；即使系统迁移工具带走了 `hosts.enc` 文件，新机的 Keystore 密钥也不同，文件无法解密 → App 会以**空列表**启动，旧数据不可恢复 |
| 系统/安全软件清理了应用数据，或 Keystore 密钥失效 | 同上：`hosts.enc` 无法解密时 App 会安全地按空存储启动（不崩溃）。重新录入凭证即可 |
| 只是界面异常 | 从最近任务里划掉 App 再重新打开；仍为空就看上面几条 |
| 覆盖安装了**不同签名**的 APK | 系统通常会阻止安装；若你卸载后重装，数据已随之删除 |

> App **没有云端同步/导出凭证**功能，这是有意的安全设计；重要主机的 SSH 登录方式和 `dsh web`
> 凭证请注意自行妥善保管（不要把 token 明文写在共享文档里）。

如果排除了以上原因、列表仍然为空且你认为数据存在，请按 §12 的模板反馈，并附上
「是否卸载/换机/恢复过系统」「Android 版本」「App 版本」。

## 15. SSH 密钥管理相关问题（v0.2.0）

> 入口：**「更多」（⋮）→ SSH 密钥管理…**；编辑主机时点 **管理 SSH 密钥…** 也可进入。
> 密钥与主机凭证在同一个加密文件里；**App 不提供密钥导出文件/二维码**（只能复制文本）。

### 15.1 找不到「SSH 密钥管理」入口

* 主界面右上角 **「更多」（⋮）** → 菜单里选择 **SSH 密钥管理…**。
* 编辑主机 → 认证方式选「私钥」→ 点「管理 SSH 密钥…」也可以进入。

### 15.2 生成密钥失败 / 很慢

| 现象 | 说明与处理 |
|---|---|
| 点了「生成新密钥」后按钮灰一会儿 | 正常：RSA 3072 可能需要 0.5–2 秒，4096 更久（在后台线程生成，不会卡死界面） |
| 生成失败，提示内部错误 | 换 **RSA 2048** 再试一次（兼容性/速度都更稳）；仍有问题重启 App 再试 |
| 手机很旧、生成经常失败 | 改用 **导入密钥对**：在电脑上用 `ssh-keygen -t rsa -b 3072 -f phone_key` 生成，导入私钥、公钥装远端 |

> App 生成的是 RSA 密钥（2048/3072/4096，默认 3072）。暂不支持在 App 内生成 ed25519。

### 15.3 导入密钥失败

| 提示 | 原因 | 解决 |
|---|---|---|
| 无法识别为私钥 / 格式错误 | 粘贴的不是私钥全文，或选错文件 | 私钥应以 `-----BEGIN OPENSSH PRIVATE KEY-----` 或 `-----BEGIN RSA PRIVATE KEY-----` 开头、到对应 `-----END ...-----` 结束；不要把 `.pub` 公钥当私钥导入 |
| 私钥口令错误 | 口令填错 / 私钥其实没有口令却填了内容 | 确认口令大小写；没有口令就把口令留空。口令错误时**不会保存**，可重新导入 |
| 公钥与私钥不匹配 | 粘贴的公钥行不是这把私钥对应的公钥 | 删掉公钥行让它自动推导，或粘贴正确的 `id_xxx.pub` 内容 |
| 文件过大 / 无法读取 | 超过 1 MiB 或不是文本文件 | 确认是文本私钥文件；用文本编辑器另存后再选 |
| 导入后连不上（ed25519） | 手机系统不支持该密钥类型 | 改用 RSA/ECDSA：在电脑上重新生成或转换后导入 |

> 导入完成后：删除手机上的临时私钥文件、清空剪贴板（安全习惯，见 [docs/security.md §3](security.md#3-ssh-密钥生命周期v020)）。

### 15.4 「所选密钥已不存在，请重新选择」

* 说明这台主机引用的密钥**已被删除**（或数据被清过）。这是设计行为：密钥没了，主机就不该再拿它去登录。
* 处理：**SSH 密钥管理…** 重新生成/导入一把密钥 → 把公钥装到远端 → 主机编辑页重新选择密钥 → 保存。
* 若只是想在多台主机间换密钥：编辑每台主机，改选同一把即可，不用重建主机。

### 15.5 删除密钥后发现主机连不上

* 删除前的警告里会写「被 N 台主机使用」；删除后这些主机的私钥登录会报「所选密钥已不存在」。
* 恢复方法：重新生成/导入密钥（如果还是同一把公钥，远端 `authorized_keys` 不用改）→ 到受影响主机里重新选择。
* 如果旧密钥的公钥还在远端 `authorized_keys` 里，你也可以选择重新生成**不同**的密钥对，再把新公钥加进去。

### 15.6 升级到 v0.2.0 后主机连不上 / 找不到原来的私钥

* 正常情况下升级会自动迁移，不需要手动操作。若提示「所选密钥已不存在」或密钥列表为空：
  * 确认是**覆盖安装**（同一签名），不是卸载重装（卸载会删数据）；
  * 到 **SSH 密钥管理…** 看是否有「来源：旧版迁移」的条目；
  * 还是没有的话，说明旧数据可能没有被保留（例如之前卸载过）：重新生成/导入密钥，把公钥装到远端，再在主机里选择。
* 迁移后**不要**再试图在主机编辑页找「粘贴私钥」——v0.2.0 已经移除了这个入口，统一走密钥管理。

### 15.7 核对密钥指纹

* 在**远端**执行：`ssh-keygen -lf ~/.ssh/authorized_keys`，输出的 `SHA256:...` 与 App 密钥详情里的
  **直接比较**即可（App 与 OpenSSH 指纹格式一致：`SHA256:<标准 base64>`、无 `=` 填充）。
* 也可以只核对某一把公钥文件：`ssh-keygen -lf 公钥文件`。
* 指纹不一致 = 装到远端的不是这把公钥，重新复制公钥并追加。

### 15.8 「显示私钥 / 复制私钥」的安全提醒

* 私钥默认隐藏，点「显示私钥」需要二次确认；「复制私钥」会提示敏感信息风险。
* 只在**迁移密钥**等必要场景使用；复制后尽快粘贴完成并**清空剪贴板**（Android 13+ 系统会隐藏剪贴板预览，
  更早的 Android 没有这层保护）。
* 不要在他人可见处展示私钥；截图/录屏可能捕获屏幕内容（App 未禁止截屏）。

## 16. 设置页与打开方式（v0.2.5）

入口：主页 **「更多」（⋮）→「设置」**。设置页只有两个开关，**立即生效并保存在本机**
（SharedPreferences 文件 `settings`，只存布尔值，不保存任何密码/token/密钥）：

| 开关 | 默认 | 作用 |
|---|---|---|
| **通过外部浏览器连接** | **关闭** | 关闭 = 内置 WebView 全自动打开（推荐）；开启 = 隧道就绪后复制含 token 的完整网址到敏感剪贴板 + 打开浏览器首页，由你手动粘贴 |
| **自动收起内置页面的顶部横栏** | **开启** | 仅对内置 WebView 页面生效：向下滚动自动收起、滚回顶部自动展开，右侧按钮可手动收起 |

### 16.1 每主机「打开时在网址中附加 token」开关去哪了？

* **v0.2.5 已彻底删除**这个每主机开关（以及 `appendToken` 字段/编辑页的 **?** 帮助）。它原来决定
  「复制 token 网址到外部浏览器」还是「App 内置 WebView 自动登录」，现在改为**全局设置**：
  **设置 →「通过外部浏览器连接」**。
* 编辑页该位置只剩一行提示：「打开方式（外部浏览器 / 内置页面）已改为全局设置：请在主页「更多 → 设置」中切换。」
* 升级后**旧主机的开关值被丢弃**，不再生效；全局默认是**关闭** = 内置 WebView。旧版加密数据里多余的
  `appendToken` 字段会被安全忽略，主机数据正常加载，不需要迁移或重新录入凭证。

### 16.2 如何切换内置页面与外部浏览器？

1. 回主机列表 → **「更多」（⋮）→「设置」**。
2. 打开/关闭 **「通过外部浏览器连接」**（开启时会弹一次安全告警，点「确定」即可；开关旁 **?** 看完整说明）。
3. 回到列表，重新点该主机的 **「打开」**（已经打开的页面不会自动切换，需要重新打开一次）。
4. 切换只影响「用哪个载体打开」，**不会修改已保存的凭证**；两种载体的登录状态互不相通，切换后重新登录一次即可。

### 16.3 内置页面横栏不自动收起

先确认设置页 **「自动收起内置页面的顶部横栏」是开启的**（默认开启；关闭后横栏始终 56dp、也不会有收起按钮）。
如果开关是开的但滚动页面时横栏不动：

* **手动收起**：点横栏右侧的「收起」按钮（向上箭头图标）→ 横栏变为一行 32dp 的主机名；
  点按这一行即可随时展开。手动方式不依赖自动滚动，因此不受上述 ROM 边界影响。
* **自动收起的触发条件**：页面向下滚动超过约 12dp 且离开顶部；滚回页面顶部（约 4dp 以内）并向上滚动才自动展开。
  在页面中部向上滚动**不会**自动展开（这是为了避免和手动收起打架），此时点按横栏或滚回顶部即可。
* **可能不生效的情况**：自动收起依赖系统 WebView 上报 `View.OnScrollChangeListener`。个别 ROM/WebView 实现
  不触发该回调时，自动收起/自动展开会失效，但**手动收起、点按展开、返回键/返回箭头都不受影响**。
* 错误面板出现时横栏会**自动展开**为 56dp，这是正常行为。
* 收起状态**不持久化**：退出页面再打开会恢复为展开态。
* 这是 v0.2.5 新增的 **UI 层特性**（自动化侧已通过编译/单测/APK 校验），真机上的滚动与动画表现仍待用户确认；
  遇到不符合预期的机型，请记录「手机型号 + Android 版本 + WebView 版本 + 操作步骤」反馈。
* 如果整个设置页都打不开：确认版本是 v0.2.5（「更多」→「关于」），旧版本没有这个入口。

### 16.4 外部浏览器模式提示 token 会复制到剪贴板 / 怎么清空

* 开启 **「通过外部浏览器连接」** 时设置页会弹一次告警：之后每次点「打开」，含 token 的完整网址都会以
  **敏感内容**复制到系统剪贴板，并打开默认浏览器首页；**App 不会直接把网址交给浏览器跳转**（会被
  Android 浏览器的 SameSite 策略拦截，显示 `authentication required`）。
* 请到浏览器**地址栏长按 → 粘贴 → 打开**；登录成功后远端会跳到不含 token 的干净地址。
* **清空剪贴板**：打开任意可输入文本的地方（如浏览器地址栏）长按 → 全选 → 删除，再复制一段无关文本覆盖；
  或重启手机。Android 13+ 系统剪贴板会隐藏敏感内容预览，但其他有权限的 App/输入法仍可能读取。
* 不想让 token 进剪贴板：到设置页**关闭**该开关，改用内置 WebView（推荐）。
* 长按主机菜单的「复制打开网址（含 token）」也会把含 token 网址放进剪贴板，同样建议用后清空。

### 16.5 升级到 v0.2.5 后行为变化

* **同一签名覆盖安装、数据保留**：主机/凭证/SSH 密钥库/已信任主机密钥都不变；没有数据迁移步骤。
* **打开方式变了**：每主机开关被删除，旧主机的选择**不再生效**；全局默认 = **内置 WebView**。
  升级后第一次点「打开」会直接进 App 内置页面，这是预期行为，不是故障。
* **编辑页少了一个开关**：原来的「打开时在网址中附加 token」和 **?** 帮助已移除，改为一行设置提示。
* **多了设置页与横栏收起**：主页「更多」菜单里新增「设置」；内置页面顶部横栏默认可收起。
* 想恢复「复制网址 + 浏览器粘贴」：设置页开启「通过外部浏览器连接」，重新点「打开」即可；
  升级本身**不需要**重新录入凭证或密钥。
* 如果升级后仍看到旧界面（没有设置菜单）：说明安装的仍是旧 APK，核对「关于」里的版本号与
  [docs/install.md §1](install.md#1-安装前的要求) 的 SHA256。
